# 受け渡しと出力、そして制約

AI が書いた JSON を、ユーザーがどうやって手順書（Word / PDF / Excel）にするか。
そして**このツールでは無理なこと**。

---

## 1. ユーザーへの受け渡し手順（これをそのまま案内する）

1. 生成した `.json` ファイルをユーザーに渡す（ファイルとして保存する）
2. CheckListMaker を起動する（インストール済みのデスクトップ版）
3. ホーム画面の **「インポート」** ボタンから、その `.json` を選ぶ
4. **確認ダイアログが出る → ここが重要（下の警告を読むこと）**
5. 取り込まれた手順書を開き、必要なら画像を貼る／文言を直す
6. エディタ上部の **「📤 他ファイルで出力」** タブから
   **「📄 Word (.docx)」「📊 Excel (.xlsx)」「📕 PDF」** を選ぶ

> UI のボタン名（実装どおり）— ホーム画面: `インポート` / `エクスポート`。
> エディタ: `▶ 実行` / `📤 他ファイルで出力` タブ、
> `💾 名前を付けて保存 (HTML)` / `🖨 印刷` / `🪧 表紙` / `↺ 一括リセット`。

### ⚠ JSON 取り込みは既存データを全部置き換える

アプリのコードはこうなっている:

```js
if (confirm('現在のデータを、読み込んだ内容で置き換えます。よろしいですか？')) {
  store.replaceState(data);
}
```

**ユーザーが CheckListMaker に既にチェックリストを持っている場合、それらは消える。**
JSON を渡すときは必ずこの1文を添えること:

> この JSON を読み込むと、CheckListMaker に今入っているデータはすべて置き換わります。
> 既存のリストがある場合は、先にホーム画面の「エクスポート」でバックアップを取ってください。

### 既存データを消さずに追加したいとき

state JSON の取り込みには「1件だけ追加」の経路が無い。回避策は2つ:

- **A. 追記する** — ユーザーに現在の state をホーム画面の「エクスポート」で書き出してもらい、
  その `checklists` 配列に新しい手順書を1件足して返す（`id` の重複に注意）。
  これが最も安全。
- **B. HTML 経由** — アプリが書き出した自己完結 HTML は
  **同一 `id` なら更新、無ければ追加**というマージ取り込みになる。ただし
  この HTML は `index.html` 全体を埋め込んだものなので、**AI が一から生成するのは非現実的**。
  既存の書き出し HTML を編集する用途にとどめる。

## 2. 出力できる形式

| 出力 | どこから | 中身 |
|---|---|---|
| **Word (.docx)** | 📤 タブ →「📄 Word (.docx)」 | 表紙（画像化）＋目次＋手順カード様式。游ゴシック。表紙・目次はページ番号から除外 |
| **PDF** | 📤 タブ →「📕 PDF」 | 印刷ビューをそのまま PDF 化。Word と同じ手順カード様式 |
| **Excel (.xlsx)** | 📤 タブ →「📊 Excel (.xlsx)」 | 列は `No / 項目 / チェック / 標準時間(分) / メモ / 詳細`。画像は手順の下に行を挿して埋め込み。表紙シート付き |
| **自己完結 HTML** | 「💾 名前を付けて保存 (HTML)」 | 単体で開いてフル編集できる HTML（画像込み） |
| **JSON** | ホーム画面「エクスポート」 | state 全体。AI に渡し直すときはこれ |
| **共有リンク** | 📤 タブ →「🔗 共有リンク」 | URL に埋め込み。**画像は落ちる** |
| ~~CSV~~ | — | 出力処理（BOM 付き UTF-8・CRLF）は実装済みだが、**現在の UI にボタンが無く呼び出せない**。ユーザーに CSV を約束しないこと |

### Word / Excel / PDF はデスクトップ版だけ

これらは Electron のメインプロセス経由でファイルを保存するため、
**`index.html` をブラウザで開いただけでは出力ボタン自体が表示されない**。
ユーザーがブラウザ版を使っているなら、デスクトップ版（インストーラ）の導入を案内する。

## 3. このツールにできないこと（AI が誤解しやすい点）

- **CheckListMaker は MCP サーバーではない。** MCP のツール定義も、CLI も、
  インポート可能なライブラリ API も存在しない。`main.js` は起動引数を一切見ず、
  ウィンドウを開いて `index.html` を読むだけの Electron GUI アプリ
- **AI が .docx / .xlsx / .pdf を直接生成することはできない。** 出力はすべて
  ネイティブの保存ダイアログを通る。AI にできるのは JSON を書くところまで
- **AI がスクリーンショットを撮ることはできない。** 録画機能は OS のグローバル入力フックと
  画面キャプチャを使うデスクトップ機能で、ユーザーが手元で実行するもの
- **ヘッドレス／バッチ実行モードは無い**

## 4. 既知の制約

| 制約 | 内容 |
|---|---|
| 共有リンク | 画像は含まれない（URL 長の都合で意図的に落としている） |
| 自己完結 HTML | メモリ上でしか保存しないため、**リロードすると編集が消える**。保存し直すと新しい HTML がダウンロードされる |
| Excel の画像 | 行高の上限 409pt（約545px）に合わせて縮小される。横位置の合わせはピクセル近似で数px ずれることがある |
| Excel の画像形式 | `png` / `jpeg` / `gif` のみ。**webp は無視される** |
| ブラウザ版の保存容量 | localStorage 上限。画像を多く貼ると保存に失敗する（デスクトップ版はファイル保存なので上限が緩い） |
| `type: "todo"` | `note` / `time` / `body` / 表紙が Word・Excel に出ない |
| 配布 .exe | コード署名していないため、ウイルス対策ソフトが警告を出すことがある |

## 5. 出力前にユーザーに確認するとよいこと

- 表紙は要るか（社外・正式文書なら要る）
- 文書番号・版数・作成者・発行日（**推測で埋めない**）
- 標準時間を入れるか（見積りに使うなら必須）
- 出力先は Word か PDF か Excel か
