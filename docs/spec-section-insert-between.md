# 仕様: 「＋」でセクション・項目をその位置に追加する

ユーザー要望（2026-09-11）。「現在『ここに追加』というボタンで追加しているが、各セクションの間に
＋アイコンを作って追加する形にしたい」。見た目は `screenshots/mock-section-add-{A,B,C,D}.png` の
4案から **D 案**をユーザーが選択。D 案の画面には、行ホバーで出ていた点線ボタン
「＋ ここに項目を追加／ここに手順を追加」は無く、**項目・手順の間も同じ丸い「＋」**にする
（最初の実装ではセクションの間だけに付けて点線ボタンを残してしまい、やり直した。経緯は末尾）。

## 項目・手順の間の「＋」

- 各セクションの `ul.items` の中で、項目と項目の間、および最後の項目の下に `li.item-gap`（高さ 14px）を
  置く。マウスを置くと青い線（`.item-gap-line`）と丸い「＋」（`.item-add`・22px）、その右に説明
  「ここに項目を追加」（テンプレート型は「ここに手順を追加」、`.item-gap-tip`）が出る。
- クリックは `data-action="insert-item-at"`・`data-section`・`data-index="<挿入先の添字>"`。
  入力欄の編集中でも押せるよう、既存の `insert-item-after` と同じ `pointerdown` 経路で処理し、
  空の項目を挿入して `pendingFocusItem` でその入力にフォーカスする。
- 旧 `.insert-after`（行ホバーの点線ボタン）は廃止。セクション見出し右の「＋」（末尾に追加）は残す。
- 項目の並べ替え（ドラッグ）は `.item` 要素だけを数えるので、`li.item-gap` が混ざっても添字は
  ずれない。印刷／PDF・書き出しには出ない。

## 見た目（D 案）

- **セクションの間**: 高さ 16px の空き（`.sec-gap`）。マウスを置くと**青い1本線**（`.sec-gap-line`）と
  中央の**丸い「＋」ボタン**（`.sec-add`・24px）が現れる。普段は何も見えない。
  ホバー中の＋は青地に白。キーボードで＋にフォーカスしたときも線と＋を出す（`:focus-visible`／
  `:focus-within`）。説明の吹き出しは出さない（`aria-label` のみ）。
- **末尾**: 幅いっぱい・高さ 40px の点線ゾーン `.sec-add-tail`「＋ セクションを追加」
  （テンプレート型は「＋ フェーズを追加」）。ホバーで青くなる。従来のボタンの `data-tip` を引き継ぐ。
- ツールバー右上の「セクションを追加／フェーズを追加」ボタンは**無くす**。「表紙を編集」は残る。
- `.sections` を縦の flex にし、`.section` の `margin-bottom` は 0（間隔は `.sec-gap` が担う）。

## 動作

- `M.addSection(checklist, title = '', index = null)`: `index` が整数ならその位置に挿入
  （0〜length にクランプ）。省略時は従来どおり末尾。既存の呼び出しは無変更で動く。
- クリックは `data-action="insert-section"`・`data-index="<挿入位置>"`。間の＋は「次のセクションの
  添字」、末尾は `sections.length`。追加後は `pendingFocusSection` でその見出し入力にフォーカスし、
  すぐ名前を打てる（項目の「ここに項目を追加」と同じ作法）。
- セクションの並べ替え（ドラッグ）は `.section` 要素だけを見るので `.sec-gap` の影響なし。
  印刷／PDF は `#app` ごと非表示なので紙面には出ない。

## テスト

- `test/model.test.js`: `addSection` の index 挿入・省略・範囲外クランプ・負数。
- 実機（Electron 31 オフスクリーン）: 項目の間のホバーで線・＋・説明が出る、クリックでその位置に
  挿入されフォーカスする、末尾の＋、テンプレート型の文言。`screenshots/v1.0.6-item-add-*.png`。

## 経緯（読み違い）

要望文の「ここに追加」は行ホバーの点線ボタンのことだったが、ツールバー右上の「セクションを追加」
ボタンと読み違えたままモック〜実装を進め、点線ボタンを残してしまった。モック D の画面には
点線ボタンが写っていなかった（ホバー時にしか出ないため）ので、モックの見た目と実装が食い違った。
要望の名称が画面の要素と一致しないときは、着手前に「どのボタンか」を確認する。
