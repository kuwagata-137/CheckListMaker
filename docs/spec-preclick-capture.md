# 仕様: クリック直前の画面を撮る（v1.0.8・作業2）

## 要望

- 2026-09-29：「キャプチャ撮影でクリックした直後の画面が撮られていることが多いです。クリックする直前の画像を
  キャプチャするようにしてください。」

## 今の仕組み（v1.0.7）と、直後の画面になる原因（コードを読んで確認）

- 録画中は 500ms ごとに `screenshot-desktop` で裏撮りし、最新の1枚（`preFrame`）だけを持つ。mousedown で
  その1枚を**使い切る**（`takeFreshPreFrame`）。
- `screenshot-desktop` は1枚ごとに外部プログラム（cmd → .bat → .NET）を起動するため、1枚に 0.5〜1 秒かかる。
  補充が間に合わないと、**クリックの後にその場で撮る**（`capture.source: "ondemand"`）＝クリック直後の画面。
  例：メニューを開くクリックのあと、1秒以内に項目をクリックすると、2回目はメニューが閉じた後の画面になる。
- 文字入力・ショートカットは保存キューの中で撮る。クリックで入力を区切るとき、先にクリックが裏撮りの1枚を
  使い切るため、入力の画像がクリック後の撮影になりやすい。

## 方式

- 録画中だけ、常駐の撮影プロセス `capture-host.js`（Electron の utilityProcess。`uia-host.js` と同じ作り：
  koffi・Per-Monitor V2 の DPI 対応・子が落ちても録画は続く）を起動する。
- GDI（`CreateDIBSection`＋`BitBlt`）で、カーソルのあるモニタを **100ms ごと**に撮り、直近の数枚をリングに持つ。
  各1枚には撮影の開始・撮り終えの時刻（`GetTickCount`＝OS 起動からの ms）とモニタの矩形（物理 px）を付ける。
- クリック（mousedown）・キー押下の**イベント時刻**（uiohook の `time`。Windows ではフックが OS から受け取る時刻で、
  `GetTickCount` と同じ基準）より**前に撮り終えた最新の1枚**を使う。**使い切らない**（同じ1枚を続けて使ってよい）。
- 該当する1枚が無いとき（撮影が止まっていた・別のモニタ）は、撮影プロセスにその場で撮らせる（`grab`）。
  撮影プロセスが無いときは従来の `screenshot-desktop`。
- 画素は BGRA。GDI はアルファを 0 にするので 255 に埋めてから親へ送る。PNG への変換は main で
  `nativeImage.createFromBitmap(...).toPNG()`。
- ガジェットは `setContentProtection(true)` で撮影から除外されている（GDI の撮影にも効く）。
- `CAPTUREBLT` は使わない（撮るたびにマウスカーソルがちらつくことがあるため）。Windows 10/11 は画面を
  DWM が合成しており、半透明のメニューなども写る。
- Linux（開発用）は従来どおり（`screenshot-desktop` の裏撮り）。

### 「前に撮り終えた」の判定（純関数 `pickFrameBefore`）

- 条件：①撮り終えの時刻 ≤ イベント時刻 ②イベント時刻 − 撮り終えの時刻 ≤ 1000ms（撮影が止まっていたときの
  古い1枚は使わない）③イベントの座標（物理 px）がその1枚のモニタの矩形の中。該当の中で撮り終えが最も新しいもの。
- 撮り終えで判定する理由：1枚の撮影に約 40ms かかり、その間にクリックへの反応が画面に出ると写り込み得るため。
  撮り終えてからクリックされた1枚だけを使う（最大で「間隔＋撮影時間」≒0.15 秒前の画面）。
- 32bit のティックは約 49.7 日で一周するので、差は符号付き 32bit で比べる（`tickDiff`）。

## スパイクの結果（2026-09-29・1920×1080・`tools/capture-spike/measure.js`・各8秒）

本番（`capture-host.js`）と同じ写し方（`RtlMoveMemory` で DIB のメモリからリングの枠へ1回写す）で測った値。

| 間隔 | 1枚の撮影時間（平均／95%／最大） | CPU（1コアあたり） | 4枚のメモリ |
|---|---|---|---|
| 100ms | 40.0／43.3／44.7ms | 5.1% | 31.6MB |
| 150ms | 39.5／42.2／43.2ms | 5.1% | 31.6MB |
| 200ms | 39.9／41.9／43.2ms | 2.1% | 31.6MB |

- 撮影時間の大半は GPU からの読み戻しの待ちで、CPU はあまり使わない。**間隔は 100ms に決めた**
  （CPU 5.1%＝4コアの PC なら全体の約 1.3%）。
- 最初は `koffi.view` で DIB のメモリを直接のぞいていたが、Electron の中では外部メモリの ArrayBuffer が
  禁止されていて、撮影プロセスが「napi_get_last_error_info」で落ちた（素の Node では動く）。`RtlMoveMemory` に変えた。
- Electron 31 の中で確かめた値（撮影プロセスを起動して）：その場の1枚 55ms、「前に撮り終えた1枚」の受け取り 18ms、
  PNG への変換 70ms（1920×1080・約 660KB）。古すぎる時刻を渡すと null を返す。
- 大きいモニタで1枚が長いときは、次の撮影まで最低 30ms 休む（間隔が「撮影時間＋30ms」に延びる）。
- リングの枚数は1枚の大きさで決める：合計 64MB 以内・2〜5枚（1920×1080 なら5枚＝約 40MB＝約 0.5 秒ぶん。
  4K は2枚）。取り出しの要求は通常 50ms 以内に届くので、2枚あれば「前に撮り終えた1枚」は残っている。

## 対象の操作と、使う時刻

| 操作 | 使う時刻 | 備考 |
|---|---|---|
| クリック（左・右） | mousedown の `time` | 右クリックの画像はメニューが開く前。続けてメニューの項目をクリックすると、その画像はメニューが開いた状態 |
| ドラッグの始点 | mousedown の `time` | 終点（`NNNe.png`）は従来どおり離した後にその場で撮る |
| 文字入力の確定 | 確定のきっかけ（クリック・Tab・Enter・ショートカット）のイベント時刻 | きっかけがクリックでも、クリック前の画面になる |
| Enter・ショートカット | keydown の `time` | 押した瞬間より前の画面（＝効果が出る前） |

## サイドカー（`NNN.json`）の `capture`

- `source`：`"preclick"`（撮影プロセスの直前の1枚）／`"grab"`（撮影プロセスでその場）／`"ondemand"`（従来の
  `screenshot-desktop` でその場）／`"precapture"`（Linux などの従来の裏撮り）
- `ageMs`：`preclick` のとき、イベントの何 ms 前に撮り終えた1枚か（それ以外は `null`）

## 実装

- 新規 `preclick-frames.js`（純関数。テスト対象）：`tickDiff`・`pickFrameBefore`・`fillAlpha`・`ringSizeFor`・
  `nextCaptureDelay`。
- 新規 `capture-host.js`（子）と `capture.js`（親の窓口：起動・停止・Promise で返す・子が落ちたら null）。
- `main.js`：録画開始で `capture.start()`、停止で `capture.stop()`。撮影プロセスが動いている間は従来の
  500ms の裏撮りを止める。クリック・キー操作・入力の確定は、イベント時刻を渡して `capture.pickBefore()`。
