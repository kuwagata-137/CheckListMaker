# 仕様: ↑↓ で順番を入れ替えた手順を、画面上の同じ位置に残す（v1.0.12）

## 要望（2026-10-13）

「項目の順序を上下矢印のボタンで入れ替えた時に、画面中央に表示される項目が移動対象の項目でなく、移動後のビューに
なってしまう。順序を入れ替える項目は大体何度か移動させることになるので、移動させた項目が常に中央（画面は移動しない）の
ままで、移動のボタンをカーソル移動なしで何回かクリックできる仕組みにしてほしい」。

## 直す前の動き（原因）

- ↑↓（`move-item-up` / `move-item-down`）は `pointerdown` で `M.moveItem` を commit し、`render()` が `#app` を
  丸ごと作り直す。文書のスクロール量（`window.scrollY`）はそのまま残る。
- そのため、画面の同じ高さには入れ替わった隣の手順が来て、動かした手順は隣の手順の高さぶん上（下）へずれる。
  手順の高さは画像・本文・メモで大きく違うので、ずれも大きい。2回目を押すにはマウスを動かして探し直す必要があった。

## 決定

- 押した ↑↓ の手順（行 `.item[data-item]`）の画面上の上端が、押す前と押した後で同じになるよう、描き直した直後に
  文書をスクロールし直す（`scrollBy`・アニメーションなし）。
- ↑↓ は行の1行目の右端に、行の上端から決まった距離で付いている（`docs/spec-item-text-wrap.md`）。行の上端を戻せば、
  ボタンもマウスの下に戻るので、マウスを動かさずに続けて押せる。
- 測るときは行の `transform` を一時的に外す。ToDo 型の `.item:hover { transform: translateY(-1px) }` があり、押す前（ホバー中）
  と描き直した直後（まだホバーが付かない）で1pxずれ、押すたびにたまっていくため。
- 編集ズーム（`#app` の `zoom`）が1でないとき、`getBoundingClientRect` の値が画面 px か内部 px かは Chromium の版で違う
  （M128 で標準化）。印刷プレビューの改ページ線と同じく、高さの決まった物差しを差して実測した倍率で画面 px に直す。
- 文書の先頭・末尾の近くでスクロールしきれないぶんは、そのままずれる（スクロールできる量の外へは動かせないため）。
- サイドバーのカードは、今までどおりサイドバーのスクロール位置を保つ（カードは1枚ぶん動く）。

## 取り込みウィザードの ↑↓

- 画像インポートの取り込みウィザードの ↑↓ も、同じ考え方で、描き直した後に一覧（`.iw-list`）の `scrollTop` を直し、
  動かした行をマウスの下に残す（要望と同じ原理。行の高さは一定だが、直さないと1行ぶんずれる）。

## 実装

- `keepItemOnScreen(itemId, mutate)`：`printRuler` で編集ズームの座標系の倍率（`unit`）を測り、`mutate`（`store.commit`。
  `render()` まで同期で終わる）の前後で行の上端（`itemRowTop`。`transform`・`transition` を一時的に外して測る）を測って、
  差を `window.scrollBy` に渡す。差の換算は純関数 `keepPositionScrollDelta(before, after, unit, zoom)`（`window.__test__`）。
- **端数のたまりを防ぐ**：スクロール量は整数 px に丸められるため、毎回「今の位置」に合わせると、行の高さの端数が同じ向きに
  たまり、続けて押すたびに 0.6px ほどずつずれた（Electron 31 で実測）。同じ手順を続けて動かしている間は、最初に押したときの
  高さ（`keepItemPin`）へ戻す。手でスクロールしたなどで2px以上違っていたら、その位置で測り直す。

## 確認（Electron 31・オフスクリーン・窓 1100×800）

16 手順（画像入りの高い手順が3つ、3行の手順、メモ入りの手順を含む）で、同じ座標を7回クリックした。

| 型 | 編集ズーム | 操作 | 7回とも同じ ↑↓ がマウスの下 | ボタンの上端の揺れ |
|---|---|---|---|---|
| テンプレート | 100% | 手順13を ↑（画像入りの手順をまたぐ） | はい | 330.2〜330.9px（±0.5px） |
| テンプレート | 83% | 手順3を ↓ | はい | ±0.6px |
| ToDo | 100% | 手順13を ↑ | はい | ±0.5px |
| ToDo | 83% | 手順3を ↓ | はい | ±0.5px |

- 端数を直す前は、同じ7回で上端が 330.9 → 334.5px と押すたびに下へずれていった。
- 文書の先頭（または末尾）に着くと、それ以上はスクロールできないので、そこから先は行がずれる（先頭まで ↑ した7回目で確認）。
- 画像：`screenshots/v1.0.12-move-keep-position.png`（手順13を7回 ↑ した後。↑ がマウスの下でホバー表示のまま）。
- テスト：`test/movekeepposition.test.js`（換算・配線・端数がたまらないこと・取り込みウィザード）。
