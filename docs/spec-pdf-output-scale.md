# 仕様: PDF出力の倍率・用紙・向き指定

ユーザー要望（2026-09-08）。ワイド画面のスライド画像だけを貼ったリストを PDF 出力すると
余白が大きすぎて不格好になるため、**出力の倍率**を操作して1ページに3枚入るように
したい。UI はユーザー提示のイメージどおり「倍率 [100]%」「用紙 [A4▼][縦▼]」の2行。

## UI（印刷プレビューのバーに追加）

`openPrintPreview` のバー（「画像の配置」の行の下）に2行を追加する。

- **倍率** … 数値入力（30〜200・5刻み・既定 100）＋「%」。**PDF 出力にのみ効く**
  （🖨 印刷は OS の印刷ダイアログ側に倍率があるため触らない）。Electron 版のみ表示。
- **用紙** … サイズ（A4／A3／B4／B5／Letter）と向き（縦／横）のドロップダウン。
  **印刷と PDF の両方**に効く（@page の size を差し替える）。
- 値は `state.settings.pdfScale / pdfPaper / pdfOrient` に保存（`commitInPlace`・
  `history:false`＝Undo 履歴に積まない。サムネイルサイドバーの開閉と同じ扱い）。
  初期値は 100％・A4・縦。
- ツールバー直下の 📕 PDF（プレビューを経ない出力）も同じ設定値を使う。
- プレビューは用紙サイズ・向きで紙面の幅を変え、倍率は `zoom` で近似表示する。
- **改ページ線**（2026-09-09 追加 / 2026-09-10 に実位置へ是正）。紙面は常に用紙の実寸で
  組み、モーダルに入りきらない用紙（A3・B4・横向き）は `transform: scale()` で縮小して
  見せる。`max-width: 100%` で潰すと padding が 15mm/25mm のまま本文幅だけ狭まり、
  折り返し＝行数が実出力とずれてしまうため。プレビューは1枚の連続した紙なので
  `@page` の上下余白はページごとには入らず、本文は「1ページ分の本文高さ
  （用紙高 − 30mm）」で積み上がる。表紙・目次は `break-after: page` で
  1ページを丸ごと使うため、その下端を次ページの起点に取り直す。
  引き直しは描画時・画像のデコード完了時・ウィンドウのリサイズ時。
- **`break-inside: avoid` の送りを再現する**（2026-09-10）。当初は1ページ分の高さで
  等間隔に線を引くだけだったため、線が手順カードの途中を横切り、送りが起きるたびに
  以降のページが累積してずれていた。いまは次のようにする。
  - 途中で切らない塊（`PRINT_ATOM_SEL` ＝ `.print-step` / `.print-todo` /
    `.print-toc-sec` / `.print-body table` / `.print-img`）を実測する。入れ子は外側だけ。
  - 純関数 `paginateBreaks(blocks, contentH, total, start)` が、境界にかかった塊が
    1ページに収まるならその塊の**先頭まで改ページを繰り上げる**。収まらない塊は
    実際にも分割されるのでそのまま境界で切る。送りは連鎖する。
  - 送り先に**枠の上端**を使うので、ページ境界で捨てられる上マージンも自然に合う。
  - `.print-step`（薄塗りのカード）にも `break-inside: avoid` を足した。中身の
    `.print-step-keep` だけを avoid にしていた頃は、枠の上辺と padding だけが
    前ページに取り残されて切れて見えた。
  - 目次が2ページ以上になる場合も同じ計算で刻む。紙面の下 padding（15mm）には本文が
    無いので、そこまでは線を引かない。
  - **完全一致は保証しない。** Chromium の組版には孤立行（orphans/widows）など他の規則も
    あるほか、表紙は `.cover` が 794×1123px＝A4 実寸固定なので、A3・B4・横向きでは
    表紙の下端 ≠ ページ境界になる（既知の制約。下記「制約」参照）。
  - 検証: A4/A3/B4/B5/Letter × 縦横 × 1列/2列で、CSS multi-column（段組みの分割にも
    `break-inside: avoid` が同じように効く）に同じ内容を流し込み、**どの手順が何ページ目に
    載るかが Chromium 自身の分割結果と一致すること**を確認した。

## 実装

- **倍率**: `printAPI.savePdf({ title, scale })` に倍率（1=100%）を渡し、main.js の
  `printToPDF` に `scale` オプションとして与える（Chromium の対応範囲に合わせ
  0.3〜2.0 にクランプ）。
- **用紙・向き**: `preferCSSPageSize:true` のため printToPDF の pageSize/landscape は
  効かない。`<style id="print-page-style">` を head 末尾に注入して
  `@page { size: <幅>mm <高さ>mm; }` と `@page coverpage { size: … }` を上書きする
  （後勝ちのカスケードで基本の margin 15mm 25mm / coverpage margin 0 は維持）。
- 用紙寸法は CSS キーワードでなく **mm 実寸**で指定する。B4/B5 は日本で一般的な
  **JIS 寸法**（B4=257×364・B5=182×257）を使う（CSS の `size: B4` は ISO 寸法で
  日本の B4 と異なるため）。A4=210×297・A3=297×420・Letter=215.9×279.4。
- 純関数 `clampPdfScale(v)` / `pdfPaperDims(paper, orient)` / `pdfPageStyleCss(paper, orient)`
  を `window.__test__` に公開し、`test/pdfout.test.js` で検証する。

## 制約（既知）

- 表紙（カバーページ）は A4 実寸（794×1123px）で作られているため、A4 以外の用紙では
  表紙が紙面いっぱいに広がらない（左上寄せ）。表紙付きリストは A4 のまま使う想定。
- 倍率はページ全体の描画スケール。余白（15mm/25mm）は紙側の値のままで、
  内容だけが縮む（＝ワイド画像なら 70% 前後で3枚/ページに入る想定）。
- **画像だけは倍率を明示的に掛ける必要がある**（2026-09-09 に修正）。プレビューの
  `zoom` も `printToPDF({scale})` も「レイアウト幅を 1/倍率 に広げてから倍率で描く」
  ズーム意味論のため、`width: 100%` / `48%` のような**親基準の % は広がった親と相殺されて
  縮まない**。文字・余白・枠のような絶対単位だけが縮み、画像が取り残されていた。
  対策として CSS 変数 `--print-img-scale` を `.print-img` の幅に掛け、同じ倍率を
  プレビュー（`.pp-zoom` のインラインスタイル）と PDF（`pdfPageStyleCss()` が出す
  `#print-root`）の両方から降ろす。`max-height`（210mm/140mm）は絶対単位なので
  二重には掛からない。ブラウザの `🖨 印刷` は倍率を OS のダイアログに任せる仕様のため
  等倍（1）のまま。
