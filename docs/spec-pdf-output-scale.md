    載るかが Chromium 自身の分割結果と一致すること**を確認した。

## 実装

- **倍率**: `printAPI.savePdf({ title, scale })` に倍率（1=100%）を渡し、main.js の
  `printToPDF` に `scale` オプションとして与える（Chromium の対応範囲に合わせ
  0.3〜2.0 にクランプ）。
- **用紙・向き**: `preferCSSPageSize:true` のため printToPDF の pageSize/landscape は
  効かない。`<style id="print-page-style">` を head 末尾に注入して
  `@page { size: <幅>mm <高さ>mm; }` と `@page coverpage { size: … }` を上書きする
  （後勝ちのカスケードで基本の margin 15mm 25mm / coverpage margin 0 は維持）。
- 用紙寸法は CSS キーワードでなく **mm 実寸**で指定する。B4/B5 は日本で一般的な
  **JIS 寸法**（B4=257×364・B5=182×257）を使う（CSS の `size: B4` は ISO 寸法で
  日本の B4 と異なるため）。A4=210×297・A3=297×420・Letter=215.9×279.4。
- 純関数 `clampPdfScale(v)` / `pdfPaperDims(paper, orient)` / `pdfPageStyleCss(paper, orient)`
  を `window.__test__` に公開し、`test/pdfout.test.js` で検証する。

## 制約（既知）

- 表紙（カバーページ）は A4 実寸（794×1123px）で作られているため、A4 以外の用紙では
  表紙が紙面いっぱいに広がらない（左上寄せ）。表紙付きリストは A4 のまま使う想定。
- 倍率はページ全体の描画スケール。余白（15mm/25mm）は紙側の値のままで、
  内容だけが縮む（＝ワイド画像なら 70% 前後で3枚/ページに入る想定）。
- **画像だけは倍率を明示的に掛ける必要がある**（2026-09-09 に修正）。プレビューの
  `zoom` も `printToPDF({scale})` も「レイアウト幅を 1/倍率 に広げてから倍率で描く」
  ズーム意味論のため、`width: 100%` / `48%` のような**親基準の % は広がった親と相殺されて
  縮まない**。文字・余白・枠のような絶対単位だけが縮み、画像が取り残されていた。
  対策として CSS 変数 `--print-img-scale` を `.print-img` の幅に掛け、同じ倍率を
  プレビュー（`.pp-zoom` のインラインスタイル）と PDF（`pdfPageStyleCss()` が出す
  `#print-root`）の両方から降ろす。`max-height`（210mm/140mm）は絶対単位なので
  二重には掛からない。~~ブラウザの `🖨 印刷` は倍率を OS のダイアログに任せる仕様のため
  等倍（1）のまま。~~ → v1.0.8 で印刷にも同じ倍率を掛ける。
  → **v1.0.9 で `--print-img-scale` は不要になり削除した。** 画像の大きさはページを組むときに px で
  決めて `<img>` に書くので、`zoom` だけで文字と一緒に縮む。

## ページ範囲（2026-09-11 追加）

### 実測した Chromium の改ページ（Electron 31 = Chromium 126 の printToPDF）

仕組みを決める前に、ページ数と PDF のアウトライン（見出し → ページ）で実際の出力を調べた。
スクリプトはスクラッチパッドの使い捨て（`exp_breaks.js` / `exp_where.js` / `exp_app_print.js`）。

| 調べたこと | 結果 |
|---|---|
| `break-inside: avoid` の塊が1ページより大きく、ページの途中から始まる | **次ページへ送られ**、そこで分割される（その場では切らない） |
| 同上で、中に `avoid` の塊（画像など）がある | 外側ごと次ページへ送られ、そのページで中の塊の境目で切れる |
| 1ページより背の高い画像 | 次ページへ送られ、そこで切れる（画像は途中で切れる） |
| 見出し＋最初の項目を `break-inside: avoid` の枠で包む | 収まる場合は一緒に送られる。**最初の項目が1ページより大きいと、見出しだけのページができる** |
| 見出しに `break-after: avoid` | 収まる場合は一緒に送られる。最初の項目が1ページより大きくても、**見出しと項目の先頭が同じページに残る** |
| 手順の見出し行にも `break-after: avoid` | 画像のない手順では指定がカードの外まで伝わり、次のフェーズ見出しの前で改ページできなくなる（採らない） |
| ルートの `zoom: s` と `printToPDF({ scale: s })` | 0.5／0.7／0.85 でページ数が一致（同じ組版） |
| 実アプリ（A4縦・100%・1列）の試験データ | 今の CSS では見出し2・3が最初の手順と別ページ。見出しに `break-after: avoid` を足すと、どの用紙・倍率でも同じページになった |
| 実アプリ（A4横・B5横・100%） | 画像が1ページの本文より高くなり、手順の見出し行と画像が別ページ・画像が途中で切れる（14手順で26ページ） |

### フェーズ見出しと最初の項目を離さない

> v1.0.9 では、フェーズ見出しと最初の手順を同じ半分に置いて1ページずつ組むので、下の
> `break-after: avoid` は不要になり削除した（手順のページは Chromium の改ページに任せない）。

- `.print-section-title { break-after: avoid; }` を足すだけにする（テンプレート型・ToDo 型の両方）。
- 当初案の「見出し＋最初の項目を `div.print-sec-lead`（`break-inside: avoid`）で包む」は採らない。
  上の実測のとおり、最初の項目が1ページより大きいと見出しだけのページができるため。
- プレビューの改ページ線も同じ規則で引く：見出しと最初の項目をひとまとまりとして送る。
  見出しがページの先頭にあるときは送らず、最初の項目の中（画像・表の境目）で切る。

### 改ページの規則を実出力に合わせる（プレビューの赤い破線）

> v1.0.9 では、この規則は**目次**（表紙の直後。今までどおり Chromium の改ページに任せる）を
> プレビューで1ページずつの紙に分けるときだけ使う。手順のページには使わない。

`paginateBreaks(blocks, contentH, total, start)` の規則を実測どおりに改める。

- `blocks` は「途中では切らない塊」の `{ top, bottom, kids }`（上端の昇順）。`kids` は中にある
  切らない塊（手順カードの中の画像・表など）で、同じ形の入れ子。
- ページの終わりをまたぐ塊が**ページの途中から始まっていれば、その塊の先頭で改ページする**
  （1ページに収まらない塊でも送る）。
- **ページの先頭から始まる塊**は送れないので、その `kids` について同じことを調べる。
  該当が無ければページの終わりで切る。
- フェーズ見出しは、そのフェーズの最初の項目とひとまとまりの塊にする（上端＝見出しの上端、
  `kids`＝最初の項目の中の塊）。見出しだけのフェーズは見出しを1つの塊にする。
- 完全一致は引き続き保証しない（行単位の孤立行の規則などは追わない）。
- **精度の実測**（2026-09-29）：固定の試験文書×9構成と、ばらばらの試験文書（画像の枚数・縦横比・本文の
  長さを乱数で変えたもの）×6構成、計47通り・目印2044個（見出し・手順カード・手順の見出し行・最初の画像）で、
  プレビューの計算と実際の PDF のページを突き合わせた。**外れは40個（約2%）で、すべて画像2列の3構成**。
  原因は画面と印刷の組版の ±1〜2px の差（例：ページの終わりを 2.2px 超えると計算した塊が実際には収まった。
  逆向きの例もある）。「この幅までは超えても収まる」とみなす許容幅を −3〜+3px で比べ、0px が最少だったので
  足さない。
- 参考：印刷の1ページの本文の高さは、計算値（用紙の高さ − 30mm）より 0.01〜0.95px 大きかった（次の整数 px
  近くまで切り上がる。A4縦 1009.13→1009.96・A4横 680.31→680.96 など）。計算に入れても外れは減らなかった。

### 用紙に合わせた倍率の自動調整

> **v1.0.9 でやめた。** 目的は「画像がページの途中で切れない」ことだったが、v1.0.9 の手順の配置では
> 手順をページの上半分か下半分の中に置き、入りきらない画像は縦横比のまま縮めるので、倍率を変えなくても
> 画像は切れない。倍率の欄は残し、手で変えた倍率は文字と画像の大きさに効く（下の「手順の配置（v1.0.9）」）。
> 関数 `autoPrintScale`・`measurePrintFitNeeds` とテストは削除した。

- **いつ**：印刷プレビューで「用紙」「向き」「画像の配置（1列／2列）」を変えたとき。
  プレビューを開いただけでは変えない（手で決めた倍率を尊重する）。倍率欄は従来どおり手で変えられる（30〜200%）。
- **どの倍率にするか**：次の条件をすべて満たす**最大の倍率（30〜100%・5%刻み）**。
  1. どの画像も、1ページの本文の高さに収まる（画像が途中で切れない）。
  2. 手順カードの上端から最初の画像の行の下端までが1ページに収まる（手順の見出し行と最初の画像を
     同じページに載せる）。画像が1行だけの手順はカード全体。フェーズの最初の手順は、
     フェーズ見出しの上端から数える。
  - 30% でも満たせない条件（本文がとても長い手順など）は計算から外す（全体を 30% に引きずらない）。
  - A4縦は今までどおり 100% になる（画像の高さの上限 210mm が A4縦に合わせてあるため）。
- **求め方**：プレビューの紙面に候補の倍率を掛けて実際に組版し、画像と手順の高さを実測する
  （倍率を下げるほど収まりやすいので二分探索。1回の変更で5〜6回の組版）。当初は画像の縦横比から
  計算で求める純関数を考えたが、CSS の幅の計算（% 幅・余白・mm の上限）を JS に写すと食い違いの
  元になるため、実際の組版を測る方式にした。探索部分は純関数 `autoPrintScale(needsAt, pageH)` に
  切り出してテストする（`needsAt(倍率)` が「1ページに収めたい高さ（本文の内部座標）」の配列を返す）。

### 倍率を印刷にも効かせる

- 倍率は `#print-root` の `zoom` で掛ける（**印刷・PDF 共通**）。`--print-img-scale` にも同じ値を入れる。
  `pdfPageStyleCss()` が `#print-root { zoom: s; --print-img-scale: s; }` を出し、
  `applyPrintPageStyle()` を印刷（`printChecklist`）と PDF（`savePdfViaElectron`）の両方が呼ぶ。
- PDF の `printToPDF` には `scale: 1` を渡す（二重に掛けない）。上の実測のとおり `zoom` と `scale` は
  同じ組版になるので、プレビュー（`.pp-zoom` の `zoom`）・印刷・PDF の3つが同じ仕組みにそろう。
- 倍率欄をブラウザ版にも出す。ヒントは「倍率は印刷と PDF に効きます。ページ範囲は PDF だけ（空欄で最初／最後まで）」。
- OS の印刷ダイアログにも倍率があるため、そちらも変えると二重に掛かる（ダイアログは 100% のまま使う）。

### 既知の問題（v1.0.8 の変更より前からある）

  （同じ文書でも 75・80・83・84・86・87・90・95% や A4・横向きは成功。別の文書の Letter 縦・85% も成功）。

  関係ない。アプリは「PDF の保存に失敗しました」と出す。倍率を 5% 変えると出せる。

  preload で `alert`／`confirm`／`prompt` を記録だけにする（2026-09-29、この失敗の警告が作業中の画面に出続けた）。

## 手順の配置（v1.0.9・2026-09-30）

ユーザー要望（2026-09-29〜30）の要旨：

- 手順を「縦○段×横○列」のページ割で組めるようにしたい。v1.0.8 で画像の大きさが縦横比だけで決まるようになり、
  手順1つの大きさがそろったため。
- 今は手順どうしが近く、余白がページの下に寄っている。バランスよく配置したい。
- テンプレート型と ToDo 型の両方。

完成イメージは `screenshots/v1.0.9-print-layout-mock2.png`（⑤ 縦1×横1 は `v1.0.9-print-layout-mock2-1x1.png`）。
最初のモック `v1.0.9-print-layout-mock.png` は、2×2 の説明にあった「上半分・下半分（2つ割）」を全配置に当てはめて
いた（縦は 2・4・6 だけ、手順が足りない段は半分の幅で中央）。ユーザーの指摘（「半分というワードに引っ張られ過ぎ」
「3分割するとかの発想はなかったのか」）を受け、理念から組み直した。

### 考え方（理念）

- **ページ割に対して余白をバランスよく配置する。** 真ん中に寄せることではない。手順が並ぶページで、次のページへ
  送られたぶん下に余白がたまることはしない。
- **ページ割は「縦」の設定で決まり、ページの中心から等分する**（縦2＝上下2つ、縦3＝3つ、縦1＝分けない）。
  縦の割りは強制する：手順は上の区切りから入れ、フェーズは区切りの先頭から始める。
- **横の割りは強制しない**：手順が足りない段も、手順の箱で本文の左右いっぱいを使う（背景は自動のときと同じく
  左右いっぱい）。2×2 なら左上・右上・左下・右下で、手順が1つの段はその手順が左右いっぱい（上の段なら「上真ん中」）。
- **1ページに手順1つ（縦1）は上詰め**：見出しと手順をページの上に置き、手順の箱は中身の高さのまま
  （ページいっぱいに伸ばさない）。

### 設定ごとの形

| 設定 | ページ割 | 段の置き方 | 手順の箱の高さ |
|---|---|---|---|
| 縦 自動 × 横 C（横も自動なら 1） | 上半分・下半分 | 区切りに入るだけ入れ、段の間を 28〜72px でそろえる（余りは区切りの上下に分ける）。区切りより高い段は画像を縮めて収める | 中身の高さ（同じ段はいちばん高い手順にそろえる） |
| 縦 1 × 横 C | 分けない | 1ページに1段・上詰め | 中身の高さ（ページより高ければ画像を縮める） |
| 縦 2〜6 × 横 C | 縦の数で等分 | 1つの区切りに1段 | 区切りの残りの高さいっぱい（マスいっぱい） |
| 縦 2〜6 × 横 自動 | 縦の数で等分 | 1段に入る数は画像の縦横比で決める | 同上。幅は画像の幅の比で左右いっぱいを分ける |

共通：

- フェーズ見出しは、フェーズが始まる区切りの上端・左。続きの区切り・ページには見出しを出さない。
- 1ページ目は、最初の区切りだけ文書の表題の下から（区切りの位置はほかのページと同じ）。表題で最初の区切りが
  半分より埋まるときは、その区切りは表題だけにして、手順は次の区切りから入れる。
- 横 C 列の段は、段の手順の数で幅を等分する（手順が1つなら左右いっぱい）。箱と箱のあいだは 16px、区切りと
  区切りのあいだも 16px。
- 画像：縦「自動」と縦1は、手順の幅いっぱいに縦に積む（以前の「1列（大きく）」と同じ）。縮めるとき・マスの中では、
  1段に並べる枚数を変えて画像がいちばん大きく見える並べ方を選び、中央に置く（4枚なら 2枚×2段 など）。
- 空いた区切りができるのは文書の終わりだけ。
- 表紙・目次のページ、紙の余白（上下15mm・左右25mm）は今のまま。

### 設定の値

`state.settings.printGrid = { rows: '' | 1〜6, cols: '' | 1〜4 }`（`''`＝自動）。印刷プレビューのバーの
「手順の配置 縦［自動・1〜6］段 × 横［自動・1〜4］列」で選び、`setPrintGrid` で保存する（`commitInPlace`・
`history:false`）。v1.0.8 までの `printImgLayout`（1列／2列）は読まず、保存のときに消す。

### 自分で決めたこと（ユーザーの指示に無い）

1. 「縦」は 1〜6、「横」は 1〜4 まで。
2. 用紙・向きを変えたときの倍率の自動調整（v1.0.8）はやめる。自動調整の目的だった「画像がページの途中で切れない」は、
   新しい配置で必ず守られるため。倍率の欄は残し、手で変えた倍率は文字と画像の大きさに効く。
3. 手順の箱に文字が入りきらないとき（本文の長い手順を小さいマスに入れたときなど）は、はみ出した部分を隠し、
   プレビューのその手順に赤い枠と「はみ出し」、バーに「縦の段を減らすか、倍率を下げてください」を出す
   （印刷・PDF には印を出さない）。
4. プレビューは、1ページを1枚の紙にして縦に並べる（右下に「n / 全体」）。「全 N ページ」とページ範囲の上限はこの枚数。
5. 横が自動のとき、文が入りきらない手順は、入るまで幅の目安を広げる（画像の欄は 40px 以上残す）。
6. 縮めた画像は手順の中の中央に置き、画像が複数なら大きく見える並べ方を選ぶ。画像を縮めた手順で右側に余白が
   たまり、横の余白も均等にするという理念に反していたため。
7. 1ページ目の最初の区切りが表題で半分より埋まるときは、その区切りを表題だけにする。横向き・縦4 や倍率を上げたとき、
   見出しと手順が最初の区切りに入らなかったため（検証で見つけた）。
8. 縦「自動」のページ割は上半分・下半分。段の数を決めない配置なので、ユーザーが以前選んだ分け方を使う。

### 仕組み（`index.html`）

- 部品：`printDocParts(checklist)` が表紙・目次・表題・フェーズ見出し・手順の部品を作る。`printItemHtml`（手順1つ）と
  `printImgsHtml(srcs, sizes, k)`（大きさを px で書いた画像。1段に k 枚）で組み立てる。
- ページの組み立て：`composePrintPages(checklist, { paper, orient, scale, grid })`。
  1. 画像の元の大きさを読む（`loadPrintImageDims`。読めない画像は 4:3 とみなす）。
  2. 画面の外の測定用の箱（`.print-measure`。印刷と同じ倍率の `zoom`）で、表題・見出し・手順の高さを本文の
     内部座標（zoom の前の px）で測る（`printRuler` の物差しで Electron 31 の zoom の座標系をそろえる）。
  3. 純関数でページを組む：`pageDivisions`（ページの中心からの等分）、`planPrintDivisions`（フェーズと段を区切りへ）、
     `balancedGaps`・`flowRowFits`（流し込み）、`fitFlowCardImages`・`fitImagesInBox`（画像の大きさと並べ方）、
     `rowCells`・`fillRowWidths`・`packRowsByWidth`（段の中の横の位置）、`clampPrintGrid`。
     組み方は `makeFlowLayout`（縦 自動）・`makeTopLayout`（縦1）・`makeGridLayout`（縦2〜6）。
  4. ページごとに `div.print-page`（高さ＝1ページの本文の高さ − 4px ÷ 倍率。端数で次のページへはみ出して白紙が
     できないように）を作り、要素を `position:absolute` で置く（`.pl-abs`）。置いた要素には入るべき区切りの範囲を
     `data-reg="上,下,左,右"` で持たせる（検証用）。2枚目からは `break-before: page`。
- 印刷・PDF：`fillPrintRoot` が `composePrintPages` で組んで `#print-root` に入れる（非同期）。`printChecklist` は
  組み終わってから `window.print()`、`savePdfViaElectron` は画像のデコードを待ってから `printToPDF`。倍率は今どおり
  `#print-root` の `zoom`。
- 目次（表紙の直後）は今までどおり Chromium の改ページに任せる。プレビューでは `paginateBreaks` で目次の切れ目を
  求め（`measureTocSegments`）、1ページずつの紙に切り分けて見せる。
- プレビュー：`previewSheetsHtml` が表紙・目次・手順のページを1枚ずつの紙にして縦に並べる。
- 削除したもの：`printImgLayout`／`setPrintImgLayout`／`printColsClass`、`.print-cols-1/2` と `--print-img-scale`、
  `autoPrintScale`／`measurePrintFitNeeds`／`printPageBreaks`、`.print-step-keep`、`.print-section-title` の
  `break-after: avoid`、`renderPrintView`（`printDocParts` に置き換え）。ToDo の項目は見出し行を `.print-todo-head` で包んだ。
