# 仕様: 「色の設定」画面（その他の色。v1.0.14）

## 1. 目的

ユーザーの依頼（2026-11-17、文のまま）:「色を選択する機能の「その他の色」ではWindowsofficeと同じように色が設定できる画面を設計する。MultipurposeDiagramMakerで開発済みなので参考にする」

- 変更前: 色パレットの［🎨 その他の色…］を押すと、OS の色ダイアログ（`input type="color"`）が開く。
- 変更後: Microsoft Office と同じ作りの「色の設定」画面を開く。参考にするのは、MultipurposeDiagramMaker（以下 MDM）v8.34 の「色の設定」画面（関数 `ocDialog`）。
- 対象は、色パレットを使う 6 か所（4 章）。手順書のデータ形式は変えない。色は今と同じく、不透明の 16 進で持つ。
- 色パレットには「最近使用した色」の行を追加する（8 章。質問 Q2 の回答）。

用語は `用語集.md` に従う（色パレット・その他の色・「色の設定」画面・標準（タブ）・ユーザー設定（タブ））。

## 2. 決定事項

統括役のプランで、ユーザーが承認したもの（2026-11-17）:

1. MDM の `ocDialog` と同じ構成・同じ操作にする（3 章）。開いた時は「ユーザー設定」タブ。スポイトは入れない。
2. 透過性の行は入れない。CheckListMaker の色は、不透明の 16 進だけを持つため。
3. 配色はアプリの CSS 変数（`--surface`・`--border-strong`・`--text`・`--primary` など）を使い、明るい表示と暗い表示の両方で読めるようにする。並びと大きさは MDM と同じ。
4. 色パレットを使う 6 か所すべてで、［🎨 その他の色…］から「色の設定」画面を開く。［OK］では、色パレットの色見本を押した時と同じ処理（`onPick`）で色を反映する。元に戻す操作も、色見本を押した時と同じになる。
5. 「現在」の見本には、対象に今付いている色を表示する。色は、呼び出し元から `rbOpenPalette` に渡す。分からない時と「なし」の時は白。
6. 本文の文字範囲は、今と同じく開く前に保存し、［OK］の時に本文へフォーカスと選択を戻してから色を付ける。［キャンセル］・［✕］・Esc・背景のクリックでは何も変えない。
7. 「色の設定」画面を開いている間のキー操作は、この画面だけで処理し、後ろの画面（画像編集画面の Esc で閉じる・Delete で図形を消す・矢印キーで動かす、本文の入力など）に届かないようにする。
8. 色パレットは、［🎨 その他の色…］を押した時に閉じる。
9. ボタンの並びは、肯定の［OK］が上、［キャンセル］が下。グローバルのルール「確認の窓のボタンの並び」に従う。MDM と同じ。
10. 色パレットに「最近使用した色」の行を追加する。質問 Q2 へのユーザーの回答（2026-11-17）は、選択肢「最近使用色追加（推奨）」。詳細は 8 章。

Claude が決めたこと（統括役への報告に書く）:

1. 「現在」の見本に表示する色の決め方（3.5 節の表）。
2. MDM にないキー操作（Tab の循環・Ctrl＋Tab・Alt＋下線の文字。3.3 節）を追加した。下線の文字を表示する以上、その文字で項目へ移れる方が Office と同じになるため。
3. 背景のクリックで閉じる時は、`mousedown` ではなく `click` で閉じる。MDM は `mousedown` で閉じる。後ろにモーダル（表紙を編集する画面など）がある時、マウスを離した時のクリックが後ろのモーダルへ届いて、そのモーダルまで閉じてしまうことを防ぐため。
   - ダブルクリックの 2 回目の `click`（`e.detail` が 2 以上）では閉じない（統合後のコードレビューの指摘。v1.0.14）。［🎨 その他の色…］をダブルクリックすると、1 回目のクリックで「色の設定」画面が開き、2 回目の押下は画面全体を覆う背景が受けるため、開いてすぐ閉じていた。
4. 閉じた後は、開く前にフォーカスがあった所へフォーカスを戻す。手順の本文では、［キャンセル］の時も文字範囲を戻す。選んでいた文字を、選び直さずに済むようにするため。

## 3. 画面構成

並びと大きさは MDM と同じ。

| 場所 | 内容 |
|---|---|
| 上の帯 | 題「色の設定」と、右端の［✕］ |
| 左 | タブ「標準」「ユーザー設定」と、タブの中身（高さ 330px） |
| 右の列（幅 92px） | ［OK］［キャンセル］（縦に並べ、OK が上）。下に「新規」「現在」の見本（上が新規、下が現在） |

- 画面幅は 440px。画面中央に表示し、後ろに薄い背景（黒の 12%）を敷く。
- 配色: 背景 `--surface`、文字 `--text`、枠線 `--border-strong`、ボタン `--surface-2`。［OK］の枠と、マウスを置いたボタンの枠は `--primary`。［✕］にマウスを置いた時は、Windows と同じ赤（#E81123）。暗い表示では、数値欄とカラー モデルの欄も暗い配色（`color-scheme: dark`）にする。
- 重なり（z-index）は 140。色パレット（130）とモーダル（100）より上に表示する。

### 3.1 タブ「標準」

- 六角形の色見本 127 色（中心が白。中心から 6 段）と、その下の灰色 15 段（白から黒）。
- 色は MDM と同じ計算で作る。色合いは中心から見た方向、明るさは中心からの距離と上下の位置で決め、R・G・B を 51 刻みにそろえる。
- クリック: その色を「新規」にし、六角形に選択枠を付ける。
- ダブルクリック: その色で決定する。［OK］を押した時と同じ。
- 「新規」の色と同じ色の六角形があれば、タブを開いた時にその六角形に選択枠を付ける。

### 3.2 タブ「ユーザー設定」

| 項目 | 内容 |
|---|---|
| 色の面（226×150px） | 横が色合い（左 0°〜右 360°）、縦が鮮やかさ（上 100%〜下 0%）。クリックとドラッグで、丸い印の位置の色にする。色が見えるように、明るさが 0% か 100% の時は、明るさを 50% にする |
| 明るさのバー（14×150px） | 上が白、中央が今の色合いと鮮やかさの色、下が黒。クリックとドラッグで明るさを変える。印は ◀ |
| カラー モデル | RGB／HSL |
| 数値欄 3 つ | RGB: 赤・緑・青（0〜255）。HSL: 色合い・鮮やかさ・明るさ（0〜255。Office と同じ） |
| 16 進 | `#RRGGBB`。6 桁の 16 進を入力した時だけ反映する。先頭の # は省略できる |

- 色の面・明るさのバー・数値欄・16 進は、どれかを変えると、ほかの全部に反映する。入力中の欄は書き換えない。
- 数値欄に 0〜255 の外の値を入れた時は、値を 0〜255 に収める。

### 3.3 キー操作

| キー | 動作 |
|---|---|
| Esc | キャンセル（何も変えずに閉じる） |
| Enter | OK。フォーカスがボタンにある時は、そのボタンを押す |
| Tab／Shift＋Tab | 画面内の項目を順に移る。最後の項目から最初の項目へ戻り、画面外へは移らない |
| Ctrl＋Tab | タブ「標準」と「ユーザー設定」を切り替える |
| Alt＋下線の文字 | タブ「ユーザー設定」で、下線の文字の項目へフォーカスを移す。D: カラー モデル、R・G・B か U・S・L: 数値欄、H: 16 進 |

- 決定事項 7 のとおり、開いている間のキー操作は、この画面だけで処理する。後ろの画面の Esc（画像編集画面を閉じる）・Delete（図形を消す）・矢印キー（図形を動かす）・Ctrl＋Z（元に戻す）は効かない。後ろの本文に文字が入ることもない。
- Ctrl＋Z・Ctrl＋Y は、この画面の中でも効かない。Electron の実機で確認したとおり、止めないと、アプリのメニュー（編集→元に戻す・やり直す）を通して、後ろの本文の編集を元に戻してしまうため。切り取り（Ctrl＋X）と貼り付け（Ctrl＋V）は、数値欄と 16 進の欄の中だけで使える。
- 開いた時は［OK］にフォーカスを移す。
- 日本語入力の変換中の Enter は、変換の確定として扱い、OK にしない。
- この画面の上でマウスホイールを回しても、後ろの画面はスクロールしない。

### 3.4 終了操作と色の反映

| 操作 | 結果 |
|---|---|
| ［OK］・Enter・六角形のダブルクリック | 「新規」の色で決定し、`onPick` で色を反映する |
| ［キャンセル］・［✕］・Esc・背景のクリック | 何も変えずに閉じる |

- 閉じた後は、開く前にフォーカスがあった所（手順の本文、画像編集画面の［線色］などのボタン）へフォーカスを戻す。
- 手順の本文では、開く前に選んでいた文字範囲を戻す。［OK］の時は、戻してから色を付ける。

### 3.5 「現在」の見本

開いた時の「新規」は「現在」と同じ色。

| 画面 | ボタン | 「現在」に表示する色 |
|---|---|---|
| 手順の本文 | 文字色 | 選んでいる文字の表示色。色を付けていなければ、本文の既定の文字色 |
| 手順の本文 | ハイライト（文字） | 選んでいる文字に付けたハイライトの色。付けていなければ白 |
| 手順の本文 | セル塗りつぶし | カーソルがあるセルの背景色。背景がなければ白 |
| 画像編集画面 | 線色・塗りつぶし・文字色 | ボタンの色見本と同じ色。図形を選んでいれば図形の色、選んでいなければ次に描く色。「線なし」「塗りつぶしなし」は白 |

## 5. MDM との相違点

| 項目 | MDM v8.34 | CheckListMaker |

| 透過性の行 | あり | なし（決定事項 2） |

| フォーカス | 開いた時に移さない | 開いた時は［OK］へ移し、閉じた時は元の場所へ戻す |
| 最近使用した色 | 決定した色を色パレットに表示する | MDM と同じ。localStorage のキーは `checklistmaker.recentColors`（8 章） |
| 呼び出し | `ocDialog({ cur, alpha, showAlpha, onOK })` | `ocdOpen({ current, onOK, onCancel })` |

## 8. 最近使用した色

質問 Q2 へのユーザーの回答（2026-11-17）は、選択肢「最近使用色追加（推奨）」。下の内容は、統括役の連絡（2026-11-17）による。

- 位置: 色パレットの「標準の色」の行の下。見出しは「最近使用した色」。
- 中身: 「色の設定」画面で［OK］を押して決めた色を、新しい順に 10 色まで表示する。同じ色を決め直した時は、その色を先頭へ移す。Enter と六角形のダブルクリックで決めた時も、［OK］と同じ処理なので記録する。
- 色パレットの色見本・「なし」のボタン・「最近使用した色」の色見本を押した時は、記録しない（Microsoft Office と同じ）。［キャンセル］などで閉じた時も記録しない。
- 1 色目を決めるまでは、見出しと行を表示しない。
- 保存先: localStorage のキー `checklistmaker.recentColors`。手順書データのキー `checklistmaker.v1` とは別で、手順書データには入れない。値は #RRGGBB（大文字）の配列。
- 6 か所の色パレットで共通にする。どこで決めた色も、どの色パレットにも表示する。
- 行の色見本を押した時は、ほかの色見本と同じ処理（`onPick`）で色を反映する。
- localStorage の読み書きで例外が発生した時と、保存した値が読めない時は、行を表示しない。色の決定は通常どおり行う。
