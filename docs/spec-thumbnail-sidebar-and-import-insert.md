# 仕様: 編集画面のサムネイルサイドバー / 取り込みの挿入位置指定

編集まわりの2点。着手前にモック（画面案）でユーザーと確定した仕様（2026-07-25）。

- 要望1: 編集画面のサイドバーにサムネイル一覧がほしい。そこから手順の削除・順序入替が
  でき、フェーズ間の移動もできる。ただしフェーズの区切りが視覚的に分かること。
- 要望2: 録画の部分撮り直しを、既存フェーズの途中に差し込みたい。取り込み画面で対象の
  セクション（フェーズ）を選び、挿入位置をサムネイルから選べるようにしたい。

確認はモックで行った（サイドバー展開時・ドラッグ中・取り込みウィザードの3面）。
以下はそのモックで合意した内容を、実装できる粒度に落としたもの。

---

## 1. サムネイルサイドバー

### 1.1 出す条件と置き場所

- **編集画面でだけ出す（テンプレート型・ToDo 型の両方）。** ホーム（一覧）では出さない。
  当初は「ToDo 型は画像が前提でなく使い捨てのため出さない」としていたが、ToDo 型でも
  項目に画像を貼れて一覧性が要るため、2026-09-09 に両方で出す方針へ変更した。
- **区切りの呼び名だけを型で切り替える**（`thumbUnit()`）。テンプレート型は「フェーズ」、
  ToDo 型は「セクション」。影響するのは以下の4か所で、モデルの構造・ドラッグ配線・
  `.is-current` の追随は型に依らず共通。

  | 箇所 | テンプレート型 | ToDo 型 |
  | --- | --- | --- |
  | 見出しの補完（名前が空のとき） | `フェーズ N` | `セクション N` |
  | 見出しの `title` | このフェーズへ移動 | このセクションへ移動 |
  | グリップの `title` | ドラッグで並べ替え（フェーズ間も可） | ドラッグで並べ替え（セクション間も可） |
  | 削除ボタンの `title` ／ 空表示 | この手順を削除 ／ 手順がありません | この項目を削除 ／ 項目がありません |
- 画面**左**に全高で置く。`position: fixed` で置き、`body` に左パディングを与えて
  `#topbar` と `#app` を右へ寄せる。
- **幅はユーザーが変えられる**（2026-09-10 追加）。既定 **220px**・**150〜520px**。
  右端の掴み手（`.tsb-resizer`）をドラッグする。ダブルクリックで既定へ戻り、
  掴み手にフォーカスすれば ←/→ でも 16px ずつ動く。
  - **幅の出どころは `--thumbs-w` ただ1つ**（非表示 `0px` ／ 折りたたみ `30px` ／
    展開＝保存幅）。サイドバー自身の `width` と本文を押し出す `padding-left` が
    同じ変数を見るので、両者がずれようがない。
  - 上限は窓幅にも従う。本文側に **520px** は必ず残す（`#topbar` は `flex-wrap`
    しないので、ここを削ると横スクロールが出る）。**この丸めは表示のときだけで、
    保存値は書き換えない**（窓を一時的に狭めただけで設定を失わないため）。
  - **ドラッグ中は `--thumbs-w` を書くだけで保存しない。** `store.commit` は毎回
    state 全体を書き出すので、`pointermove` ごとに呼ぶと重い。保存は離した時の1回だけ。
  - 掴み手はサイドバーの innerHTML に含まれ、再描画のたびに作り直される。そのため
    リスナーは `document` へ委譲し、ドラッグ中の状態は DOM ではなく変数に持つ。
    再描画で `applyThumbsChrome()` が保存値へ引き戻さないよう、ドラッグ中は早期 return する。
- **サムネイルの大きさは幅に連れて変わる。** 画像（`.tsb-shot`）は `width: 100%` なので
  自動で追随する。番号欄の幅・番号とキャプションの字送り・`.tsb-scroll` の余白は
  `#thumbs` の `--tsb-*`（`clamp()`）で連動させる。係数は**既定の 220px でいまと同じ値**に
  なるよう決めてあるので、幅を変えていないユーザーの見た目は1pxも変わらない。
  1行1枚は維持する（複数列にすると `attachDragAndDrop` の中点判定が破綻するため）。
- **`#app` の外**（兄弟要素）に置く。`#app` には編集ズーム（`zoom: var(--editor-zoom)`）が
  掛かっており、サイドバーまで拡大縮小されないようにするため。
- 要素は **JS で生成**して `#app` の前に挿入する（`ensureThumbsEl`）。`buildStandaloneHtml`
  が書き出す body 定義に手を入れずに、単体 HTML でも同じように動く。
- 既定は**展開**。ヘッダーの `«` で折りたためる。**開閉の状態は
  `state.settings.thumbsCollapsed`、幅は `state.settings.thumbsWidth` に保存**し、
  次回起動でも引き継ぐ（どちらも `commitInPlace(..., { history: false })`＝
  Undo 履歴には積まない）。折りたたむと幅 30px の帯だけが残り、`»` で開き直せる。
  **折りたたんでも保存幅は失われない**（開き直すと元の幅に戻る）。

### 1.2 中身と、フェーズ区切りの見せ方

上から: ヘッダー（`サムネイル` ＋ `«`）→ フェーズごとのまとまり。

**フェーズの区切りは色を増やさず**、次の3つで出す（アクセントは青1色という
`docs/モダンUI仕様.md` の方針を維持する）。

1. **フェーズ見出しバー** — `--surface-2` の帯に**左 4px のアクセント色**、フェーズ名、
   件数。`position: sticky` でスクロール中も上に貼り付く。
2. **左の縦罫** — そのフェーズのカード群の左に `--border` の 2px 縦罫を通す。
3. **まとまりごとの余白と区切り線** — フェーズとフェーズのあいだに 13px の余白と上罫。

フェーズ名が空のときは「フェーズ 1」のように連番で補う（本文の入力欄は空のままでよいが、
サイドバーは見出しが無いと区切りが読めないため）。

**サムネイルカード**（1手順＝1枚）:

- 通し番号（本文と同じくフェーズをまたいだ 1..N）
- 画像は `item.images[0]`。`resolveImageSync()` を通し、参照画像には `data-img-ref` を
  付けて遅延差し替えの規約に乗せる（全再描画するとフォーカスが壊れるため）。
- 画像が無い手順も**カードを出す**（「画像なし」の枠）。番号を飛ばさず本文と一対一に保つ。
- 手順の文を1行省略で表示。空なら「（未入力）」。
- **ホバーで `⠿`（ドラッグの掴み手）と `✕`（削除）** が出る。
- 本文で編集中の手順のカードは**アクセント枠**（`.is-current`）。

### 1.3 操作

| 操作 | 挙動 |
| --- | --- |
| カードを押す | 本文の該当手順へスクロールし、文の入力欄にフォーカスする |
| フェーズ見出しを押す | 本文の該当フェーズへスクロールする |
| `⠿` を掴んでドラッグ | 並べ替え。**フェーズをまたいで**移動できる |
| `✕` | その手順を削除。確認ダイアログは出さない（本文側の `✕` と同じ。Ctrl+Z で戻す） |
| `«` / `»` | サイドバーの折りたたみ／展開 |
| 右端をドラッグ | 幅を変える（150〜520px）。折りたたむと掴み手は消える |
| 右端をダブルクリック | 幅を既定（220px）へ戻す |
| 掴み手にフォーカス＋ ←/→ | 16px ずつ幅を変える |

**ドラッグの落とし方は2通り**（本文側の既存判定と同じ）。

- 手順と手順の**あいだ**に落とす → その位置へ挿入。
- **フェーズ見出し**（または空フェーズ・カードの無いすき間）に落とす → そのフェーズの
  **先頭**へ。見出しより下のすき間なら**末尾**へ。

挿入位置は本文と同じ横破線インジケーター（`#drag-indicator`・`position: fixed` なので
サイドバーでもそのまま使える）で示す。ドロップの確定は既存の `handleMove` →
`M.moveItem`（セクション跨ぎ対応済み）に流す。**1ドロップ＝1コミット＝Undo 1回。**

### 1.4 実装方針（既存資産の再利用）

- **`attachDragAndDrop(container, onMove, opts)` を一般化する。** 現状ハードコードされて
  いるセレクタ（`.item` / `.items` / `.section` / `.grip, .step-rail`）を `opts` で
  差し替えられるようにし、既定値は現在の値のまま。本文側の呼び出しは無変更。
  サイドバーは `.tsb-card` / `.tsb-body` / `.tsb-phase` / `.tsb-grip` を渡す。
  中点判定・インジケーター表示・`__dndWired` の多重配線防止はそのまま流用する。
- **削除は既存の `data-action="delete-item"`** に相乗りする（`document` への委譲済みのため
  配線は不要）。
- `.is-current` の追随は**再描画せず**、`#app` の `focusin` で該当カードの class を
  付け替えるだけにする。

### 1.5 出さない場所

- **印刷／PDF**: `@media print` で `#thumbs` を非表示にし、`body` の左パディングも戻す。
- **単体 HTML 出力**: 出力物でもテンプレート型なら同じように使える（JS ごと同梱される）。
  隠す必要はない。
- **実行モード（プレイヤー）・ガイド小窓**: 全画面オーバーレイのため元々かぶらない。

## 2. 取り込みウィザードの挿入位置指定

`openImportWizard`（`index.html`）のフッター「取り込み先」欄を拡張する。上半分
（ステップ一覧の編集・一括置換）は**変更しない**。

### 2.1 追加する行

```
取り込み先  [リスト ▾]
取り込み方  ( ＋ 新しいフェーズとして追加 | ▼ 既存のフェーズに挿入 )
　├ 「新しいフェーズ」→  セクション名 [____]          ← 現行と同じ
　└ 「既存に挿入」  →  フェーズ [2. ネットワーク確認（4件） ▾]
                        挿入位置 [ 先頭 |4| ここ |5| ★ここに挿入 |6| ここ |7| 末尾 ]
```

- **既定は「＋ 新しいフェーズとして追加」**。現行の動き（末尾に新セクションを追加）を
  変えない。挿入は選んだときだけ。
- 取り込み先が **「（新しいリストを作成）」のときは「取り込み方」「フェーズ」「挿入位置」の
  行を出さない**（挿入先が存在しないため）。リスト選択を変えたら出し分けを更新する。
- 選んだリストに**フェーズが1つも無い**ときも同様に挿入は選べない。

### 2.2 挿入位置ピッカー

- 選んだフェーズの既存手順を**横並びのサムネイル帯**で表示する（プレイヤーの `.pl-thumbs`
  と同じ見た目の系統）。サムネは `item.images[0]` を `resolveImageSync` で解決。
- 手順と手順の**すき間**（`0..items.length` の N+1 箇所）が押せる。両端は「先頭」「末尾」。
- 選択中のすき間だけがアクセント色の縦バーになり、`3件を挿入` のように件数を出す。
- 既定の選択は**末尾**。フェーズを切り替えたら末尾に戻す。
- 手順が多いときは横スクロール（`overflow-x: auto`）。
- 画像の無い手順は「画像なし」の枠を出す（サイドバーと同じ扱い）。

### 2.3 確定処理

- 実行ボタンのラベルは結果を言う: 新規なら `取り込む`、挿入なら
  `手順5の後に3件を挿入` / `先頭に3件を挿入`。
- モーダル幅を **760px → 900px** に広げる（挿入位置ピッカーが窮屈なため）。
- `buildImportSection` から**アイテム生成部を `buildImportItems(steps, imagesByStep)` として
  切り出す**。`buildImportSection` は従来どおりセクションを返す（既存テストは無変更で通る）。
- 確定は**どちらのモードでも 1 回の `store.commit`＝Undo 1回**。

```js
store.commit((s) => {
  const c = ...;                                  // 既存 or 新規作成
  if (mode === 'insert') {
    const sec = c.sections.find((x) => x.id === destSectionId);
    sec.items.splice(clampInsertIndex(sec.items.length, at), 0, ...items);
  } else {
    c.sections.push(buildImportSection(title, steps, imagesByStep));
  }
  c.updatedAt = Date.now();
});
```

- 挿入先フェーズが**確定の直前に消えていた**（別操作で削除された）場合は、末尾に新セクション
  として追加するフォールバックにし、その旨をトーストで知らせる。
- 取り込み後は `markImported(dir)`・`goEditor(destId)`・トースト（`Ctrl+Z で取り消せます`）
  まで現行と同じ。

## 3. レンダラー純関数（`window.__test__` に公開・テスト対象）

| 関数 | 内容 |
| --- | --- |
| `thumbStepModel(checklist)` | チェックリスト → サイドバーの表示モデル（フェーズごとの手順・通し番号・サムネ元・見出し名の補完） |
| `clampThumbsWidth(px, viewportW)` | サイドバー幅の丸め（150〜520px・窓幅に応じた上限・未設定と非数は既定 220） |
| `buildImportItems(steps, imagesByStep)` | ステップモデル → 取り込む項目の配列（`buildImportSection` と共用） |
| `clampInsertIndex(len, at)` | 挿入位置の丸め（負値→0・超過→len・非数→len） |
| `insertItemsAt(section, at, items)` | セクションの指定位置へ項目を挿入（1コミット内で使う純関数） |

既存の `attachDragAndDrop` は UI 依存のため単体テストの対象外。フェーズ跨ぎ移動の不変条件は
既存の `M.moveItem` のテストで担保する（`docs/spec-dnd-image-copy-phase-move.md` と同じ方針）。

## 4. 検証

- 単体テスト（`node --test`）: 上記純関数と、サイドバー DOM が jsdom 上で
  「テンプレート型のときだけ出る／フェーズごとにカードが並ぶ／折りたたみが設定に残る」ことを確認。
- 実機検証（ユーザーの Windows 実機・`docs/残りの開発計画.md` の A に合流）:
  ドラッグでのフェーズ間移動、`✕` の削除と Ctrl+Z、印刷/PDF にサイドバーが出ないこと、
  録画 → 既存フェーズへの挿入取り込み。
