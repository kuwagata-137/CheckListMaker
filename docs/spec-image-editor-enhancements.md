# 仕様: 画像編集エディタの操作性強化（Redo・誤配置防止・8ハンドル・フリーフォーム）

ユーザー要望（2026-09-08）を受けて、実装前に確定した仕様。モック（やり直すボタン・
白丸8ハンドル・フリーフォーム描画中）でユーザーと合意済み。対象はすべて画像編集
エディタ（`openImageEditor`）内で、出力系（Word/PDF/Excel/印刷）は合成済みラスターを
使うため**波及しない**。

- 要望5: Ctrl+Z で元に戻す・Ctrl+Y でやり直す（やり直すはボタンも新設）。
- 要望6: 図形選択中に図形以外を左クリックしたとき、新図形を配置せず**選択解除のみ**。
- 要望7: リサイズハンドルを四つ角＋**各辺の中点**の8か所にし、**白丸**に変える
  （辺の中点は縦のみ／横のみのリサイズ）。
- 要望8: **フリーフォーム**描画ツール（MS Office と同様。クリックごとに頂点追加、
  始点をクリックで閉じて確定）。
- 要望9（追加 2026-09-08）: **「×」マーク**の図形挿入コマンドの追加。
- 要望10（追加 2026-09-08）: **左クリック押しっぱなし＋右クリックでハンドツールへ切替**。
  図形の配置（確定）は左クリックを離した時に統一し、押している間に右クリックしたら
  描きかけを破棄してハンドツールに切り替わる。
- 要望11（追加 2026-09-08）: **線（直線・矢印）を線として扱う**。選択時に長方形の
  破線枠（外接矩形）を出さず、線に沿った点線＋端点の白丸ハンドルだけを表示する
  （Office の直線選択と同じ見え方。ヒットテスト・変形は従来どおり線分基準）。
- 要望12（追加 2026-09-08・不具合）: **吹き出しの透過率0%で一切透けない**ようにする。
  白地の固定アルファ 0.92 をやめて不透明にし、透け具合は透過率スライダー
  （globalAlpha）だけで決める。
- 要望14（追加 2026-09-09・不具合）: **右クリックでのハンドツール切替が効かない場面がある**。
  ツール未選択のとき、ペン・ハイライト・消しゴム・モザイクを選んでいるとき、
  吹き出し・テキストのように押した瞬間に配置してしまうツールを使っているときは
  逃げ道が無かった。**どのツールでも（未選択でも）右クリックでハンドへ切り替わる**ようにし、
  吹き出し・テキストの配置も他の図形と同じ「離した時」に統一する。
- 要望13（追加 2026-09-08）: **Ctrl＋ドラッグで図形をコピー**（Office と同じ。
  元の図形は残し、複製を掴んで動かす。実際にドラッグが始まった時だけ複製を作り、
  Ctrl＋クリックだけでは何もしない。Undo 1回で複製ごと戻る）。

---

## 1. Redo（やり直す）

- `redoStack` を新設（`undoStack` と同じスナップショット形式・上限20）。
- **新規操作**（`pushUndo` が呼ばれる全地点）で `redoStack` をクリア（一般的な履歴規約）。
- 元に戻す: 現状態のスナップショットを `redoStack` へ退避 → `restore(undoStack.pop())`。
- やり直す: 現状態を `undoStack` へ退避 → `restore(redoStack.pop())`。
- ツールバーの「↶ 元に戻す」の隣に「↷ やり直す」ボタンを追加。両ボタンの disabled を
  スタック残量で同期する。
- キーボード: `Ctrl+Z`＝元に戻す、`Ctrl+Y` と `Ctrl+Shift+Z`＝やり直す
  （macOS は Cmd も可）。テキスト・吹き出しの入力中（INPUT/TEXTAREA/contentEditable）は
  発火しない（既存 `inField` ガードを流用）。アプリ本体に Ctrl+Z のグローバルバインドは
  無く、衝突しない（調査済み）。

## 2. 空白クリックは選択解除のみ

- 現状: pointerdown で「選択解除して**通常動作へフォールスルー**」するため、ツール選択中は
  そのまま新図形の描画開始（＝誤配置）になる。
- 変更: 図形を選択中に本体・ハンドル以外を左クリックしたら**選択解除して return**
  （新図形は配置しない）。もう一度クリックすれば通常どおり描画開始できる。
- `.ie-hint` の説明文も追随して更新する。

## 3. 8ハンドル＋白丸化

- `objHandles` の rect/ellipse に辺中点 `n / s / e / w` を追加（既存は `nw/ne/sw/se` のみ）。
  `applyObjDrag` は `mode` の文字包含で判定しているため、単字 kind でも
  **縦のみ（n/s）／横のみ（e/w）のリサイズ**としてそのまま動く。
- 見た目: 青塗り四角 → **白塗り＋青枠（#1a73e8）の丸**（トリミングの8ハンドルと同系の
  白地スタイル）。arrow/line の端点・吹き出しの tip ハンドルも同じ白丸に統一する。
- ホバー時のカーソルに ns-resize（n/s）・ew-resize（e/w）を追加。

## 4. フリーフォーム

- 図形タイプ `freeform`。データは `{ id, type:'freeform', pts:[{x,y},...], closed, color, size, opacity }`。
  シリアライズ（`imageEdits.objects`）は型非依存のため保存・復元コードの変更は不要。
- 操作（Office 互換）:
  - 左クリックごとに頂点を追加。カーソルまでの次の辺を点線でプレビューする。
  - **始点の近傍（許容半径内）をクリックすると閉じて確定**（closed=true）。
  - **ダブルクリックで開いたまま確定**（closed=false・折れ線）。
  - **Esc で描画を中止**（何も残さない。選択中の Esc＝解除、非描画時の Esc＝閉じる、は従来どおり）。
  - 頂点1つ以下で確定しようとした場合は破棄する。
- 描画中の未確定状態は吹き出し（activeCallout）の「begin / commit / cancel」パターンを
  踏襲し、ツール切替・エディタを閉じる操作では**確定**を試みる（頂点が足りなければ破棄）。
- 確定後は他の図形と同様: クリック選択（辺のヒットテスト）、ドラッグで移動（pts 全体を
  平行移動）、**頂点ごとの白丸ハンドル**で個別に変形、Delete／右クリックで削除、
  色・太さ・透過は共通UI。塗りは無し（枠線のみ・既存図形と同様）。
- トリミング適用時は pts 全頂点を平行移動する（`applyCrop` に freeform 分岐を追加）。

## 5. 「×」マーク図形（要望9）

- 図形タイプ `cross`。データは `{ id, type:'cross', x, y, w, h, color, size, opacity }`
  （rect と同じ矩形ベース。対角2本の線分として描画する）。
- 操作は rect と同じ: ドラッグで配置（確定はマウスを離した時）、8ハンドルでリサイズ
  （辺中点は縦のみ／横のみ）、ドラッグで移動、Delete／右クリックで削除。
- ヒットテストは対角2本の線分への距離判定（arrow/line と同じ許容幅）。
- ツールボタンはツールバーの図形群（丸の隣）に「✕」で追加。

## 6. 右クリックでハンドツールへ切替（要望10・要望14）

右クリックは「いつでもハンドツールへ逃げられる非常口」として統一する。
`contextmenu` ハンドラで次の優先順に判定する（`pointermove` では判定しない。
押しっぱなしのまま右ボタンを押した瞬間に効かせるため）。

| 順 | 状態 | 挙動 |
| --- | --- | --- |
| 1 | トリミング中（`cropMode`） | 何もしない（「適用／取消」のUIに任せる） |
| 2 | 吹き出しの本文入力中（`activeCallout`） | 何もしない（テキスト編集に任せる） |
| 3 | フリーフォーム描画中 | 描きかけを破棄してハンドへ |
| 4 | 描きかけ・配置待ちがある（`drawing` / `pendingPlace`） | 破棄してハンドへ |
| 5 | 図形の上（ツール未選択または `OBJECT_TOOLS`） | 従来どおり選択して削除メニュー |
| 6 | 上記以外 | **ハンドへ切り替える**（要望14） |

- 4 の「破棄」の対象は、矢印・直線・四角・丸・×のドラッグ描画、ペン・ハイライトの
  進行中ストローク（焼かずに捨てる）、消しゴム（`annoCtx` の状態を戻す。消した分は
  `pushUndo` 済みなので Ctrl+Z で戻せる）、モザイクの範囲選択、テキスト・吹き出しの配置待ち。
- 6 により、**ツール未選択・ペン・ハイライト・消しゴム・モザイク・テキスト・吹き出し**の
  どれを使っていても、何も無い所を右クリックすればハンドに戻れる（要望14）。
- **テキスト・吹き出しの配置も「左ボタンを離した時」に統一する**（要望14）。
  `pointerdown` では押下位置を `pendingPlace` に覚えるだけで、`pointerup`（`finish()`）で
  `beginText` / `beginCallout` を呼ぶ。**配置座標は押下位置**なので見え方は変わらない。
  `pointercancel` でも `pendingPlace` を捨てる。
- フリーフォームは「クリックごとに頂点追加」が仕様（4章）のため、この統一の対象外。
