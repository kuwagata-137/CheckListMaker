## 1. Redo（やり直す）

- `redoStack` を新設（`undoStack` と同じスナップショット形式・上限20）。
- **新規操作**（`pushUndo` が呼ばれる全地点）で `redoStack` をクリア（一般的な履歴規約）。
- 元に戻す: 現状態のスナップショットを `redoStack` へ退避 → `restore(undoStack.pop())`。
- やり直す: 現状態を `undoStack` へ退避 → `restore(redoStack.pop())`。
- ツールバーの「↶ 元に戻す」の隣に「↷ やり直す」ボタンを追加。両ボタンの disabled を
  スタック残量で同期する。
- キーボード: `Ctrl+Z`＝元に戻す、`Ctrl+Y` と `Ctrl+Shift+Z`＝やり直す
  （macOS は Cmd も可）。テキスト・吹き出しの入力中（INPUT/TEXTAREA/contentEditable）は
  発火しない（既存 `inField` ガードを流用）。アプリ本体に Ctrl+Z のグローバルバインドは
  無く、衝突しない（調査済み）。

## 2. 空白クリックは選択解除のみ

- 現状: pointerdown で「選択解除して**通常動作へフォールスルー**」するため、ツール選択中は
  そのまま新図形の描画開始（＝誤配置）になる。
- 変更: 図形を選択中に本体・ハンドル以外を左クリックしたら**選択解除して return**
  （新図形は配置しない）。もう一度クリックすれば通常どおり描画開始できる。
- `.ie-hint` の説明文も追随して更新する。

## 3. 8ハンドル＋白丸化

- `objHandles` の rect/ellipse に辺中点 `n / s / e / w` を追加（既存は `nw/ne/sw/se` のみ）。
  `applyObjDrag` は `mode` の文字包含で判定しているため、単字 kind でも
  **縦のみ（n/s）／横のみ（e/w）のリサイズ**としてそのまま動く。
- 見た目: 青塗り四角 → **白塗り＋青枠（#1a73e8）の丸**（トリミングの8ハンドルと同系の
  白地スタイル）。arrow/line の端点・吹き出しの tip ハンドルも同じ白丸に統一する。
- ホバー時のカーソルに ns-resize（n/s）・ew-resize（e/w）を追加。

## 4. フリーフォーム

- 図形タイプ `freeform`。データは `{ id, type:'freeform', pts:[{x,y},...], closed, color, size, opacity }`。
  シリアライズ（`imageEdits.objects`）は型非依存のため保存・復元コードの変更は不要。
- 操作（Office 互換）:
  - 左クリックごとに頂点を追加。カーソルまでの次の辺を点線でプレビューする。
  - **始点の近傍（許容半径内）をクリックすると閉じて確定**（closed=true）。
  - **ダブルクリックで開いたまま確定**（closed=false・折れ線）。
  - **Esc で描画を中止**（何も残さない。選択中の Esc＝解除、非描画時の Esc＝閉じる、は従来どおり）。
  - 頂点1つ以下で確定しようとした場合は破棄する。
- 描画中の未確定状態は吹き出し（activeCallout）の「begin / commit / cancel」パターンを
  踏襲し、ツール切替・エディタを閉じる操作では**確定**を試みる（頂点が足りなければ破棄）。
- 確定後は他の図形と同様: クリック選択（辺のヒットテスト）、ドラッグで移動（pts 全体を
  平行移動）、**頂点ごとの白丸ハンドル**で個別に変形、Delete／右クリックで削除、
  色・太さ・透過は共通UI。塗りは無し（枠線のみ・既存図形と同様）。
- トリミング適用時は pts 全頂点を平行移動する（`applyCrop` に freeform 分岐を追加）。

## 5. 「×」マーク図形（要望9）

- 図形タイプ `cross`。データは `{ id, type:'cross', x, y, w, h, color, size, opacity }`
  （rect と同じ矩形ベース。対角2本の線分として描画する）。
- 操作は rect と同じ: ドラッグで配置（確定はマウスを離した時）、8ハンドルでリサイズ
  （辺中点は縦のみ／横のみ）、ドラッグで移動、Delete／右クリックで削除。
- ヒットテストは対角2本の線分への距離判定（arrow/line と同じ許容幅）。
- ツールボタンはツールバーの図形群（丸の隣）に「✕」で追加。

## 6. 右クリックでハンドツールへ切替（要望10・要望14）

右クリックは「いつでもハンドツールへ逃げられる非常口」として統一する。
`contextmenu` ハンドラで次の優先順に判定する（`pointermove` では判定しない。
押しっぱなしのまま右ボタンを押した瞬間に効かせるため）。

| 順 | 状態 | 挙動 |
| --- | --- | --- |
| 1 | トリミング中（`cropMode`） | 何もしない（「適用／取消」のUIに任せる） |
| 2 | 吹き出しの本文入力中（`activeCallout`） | 何もしない（テキスト編集に任せる） |
| 3 | フリーフォーム描画中 | 描きかけを破棄してハンドへ |
| 4 | 描きかけ・配置待ちがある（`drawing` / `pendingPlace`） | 破棄してハンドへ |
| 5 | 図形の上（ツール未選択または `OBJECT_TOOLS`） | 従来どおり選択して削除メニュー |
| 6 | 上記以外 | **ハンドへ切り替える**（要望14） |

- 4 の「破棄」の対象は、矢印・直線・四角・丸・×のドラッグ描画、ペン・ハイライトの
  進行中ストローク（焼かずに捨てる）、消しゴム（`annoCtx` の状態を戻す。消した分は
  `pushUndo` 済みなので Ctrl+Z で戻せる）、モザイクの範囲選択、テキスト・吹き出しの配置待ち。
- 6 により、**ツール未選択・ペン・ハイライト・消しゴム・モザイク・テキスト・吹き出し**の
  どれを使っていても、何も無い所を右クリックすればハンドに戻れる（要望14）。
- **テキスト・吹き出しの配置も「左ボタンを離した時」に統一する**（要望14）。
  `pointerdown` では押下位置を `pendingPlace` に覚えるだけで、`pointerup`（`finish()`）で
  `beginText` / `beginCallout` を呼ぶ。**配置座標は押下位置**なので見え方は変わらない。
  `pointercancel` でも `pendingPlace` を捨てる。
- フリーフォームは「クリックごとに頂点追加」が仕様（4章）のため、この統一の対象外。

## 8. Ctrl／Shift のドラッグ中追従（要望15・要望16）

修飾キーは**押した瞬間に決め打ちせず、今の押下状態を毎回反映する**。`objDrag` に
`src`（最初に掴んだ実体・再代入しない）、`p`（最後のポインタ座標）、`shift` を足し、
`copy` の意味を「押下時の意図」から「今どちらを掴んでいるか」へ変える。

### Ctrl（コピー）

`setDragCopy(d, on)` が掴み替えを担う。

- **ON**: `applyObjDrag(d, {x: d.sx, y: d.sy})` で元を掴んだ位置へ戻し（差分0）、
  `orig` から作った複製を `objects` の末尾へ積んで、そちらを掴み直す。
- **OFF**: 作った複製を `objects` から取り除き、`d.src` を掴み直す。選択枠も元へ戻す。
- `applyObjDrag` は `orig` 基準の絶対計算なので、何度掴み替えても位置はずれない。
- ハンドル操作（`mode !== 'move'`）では働かない。Office の Ctrl＋リサイズは
  「中心から拡大」で意味が違うため。
- カーソルはコピー中だけ `copy`。ドラッグ終了（`finish` / `pointercancel`）で戻す。

### Shift（水平・垂直）

`applyObjDrag(d, p, shift)` の第3引数で受け、`|dx| >= |dy|` なら水平・そうでなければ
垂直に倒す（同値は水平）。対象は `dragConstrains(mode)` が真の move / p1 / p2 / tip /
pt\* のみ。四隅・辺のリサイズは Shift＝縦横比固定が一般的なので含めない。
第3引数を省略した呼び出しは従来どおり拘束しない。

新規に線を引くときの Shift は従来どおり45°スナップ（`shapeFromDrag`）で、
**引くときは45°・後から端点を動かすと水平垂直**という差は残す。

### 反映のタイミング

- `pointermove`: `objDrag.p` を更新し、`syncDragMods` で Ctrl・Shift を反映してから適用。
- `keydown` / `keyup`（`onDragMod`, document）: マウスが止まったままでも効くように、
  最後の座標 `objDrag.p` で再適用する。変化がないとき（キーリピート等）は何もしない。
  リスナは `close()` で必ず外す。

### Undo

`pushUndo()` は初回移動時の1回だけ。`objects` 丸ごとのスナップショットなので、
ドラッグ中に複製を何度作って捨てても履歴は1件で、Ctrl+Z 一回で完全に元へ戻る。

なお、ドラッグ中は Delete・Ctrl+Z・Ctrl+Y を受け付けない（`onKey` の先頭でガード）。
どちらも `objects` を差し替えるため、掴んでいる実体が迷子になるのを防ぐ。

## 10. 色を「線・塗り・文字」の3つに分ける（要望19・20）

色のプロパティは `color` 1つきりだった。図形は枠線しか描けず、テキストは `color` が
文字色を兼ねていたため枠線に色を付けられなかった。3つに分ける。

| プロパティ | 意味 | 既定 |
| --- | --- | --- |
| `color` | 線（枠線）の色 | `null` = 線なし |
| `fill` | 塗りつぶしの色 | `null` = 塗りなし。吹き出しだけ `#ffffff` |
| `textColor` | 文字の色（テキスト・吹き出しのみ） | 無ければ `color` |

- 塗れるのは**四角・丸・閉じた多角形・テキストボックス・吹き出し**。矢印・直線・×印は
  塗る面が無いので対象外（矢印の三角は従来どおり `color` で塗る）。
- 各 `draw*Obj` は「塗り → 線 → 文字」の順に描く（`paintPath`）。テキストは文字の外接矩形を
  `fs * 0.3` ぶん膨らませた箱に塗りと枠線を描く。
- **塗ってある図形は内側もクリックで掴める**（従来は「塗り無し前提」で内側が素通しだった）。
  多角形は新しい純関数 `pointInPoly`（レイキャスティング）で内包判定する。
- 新規テキストの枠線は**無し**（`color: null`）。付けたいときは選んでから「線色」を選ぶ。
- ツールバーの色は「線色」「塗りつぶし」「文字色」の3ボタン。文字色は書式コントロールと
  同じ条件（テキスト・吹き出しのとき）だけ出す。共通パレット `buildOfficePalette` に
  `noneLabel` を足し、線は「線なし」・塗りは「塗りつぶしなし」を出す。

### 旧データの移行

読み込み時に `normalizeObjColors` を通す（`objects` の正規化を行っている場所に足す）。

- テキスト: `color` が文字色だったので `textColor` へ移し、`color = null`（枠線なし）にする。
- 吹き出し: `textColor` に `color` を写し、`fill` に従来の白ベタ `#ffffff` を持たせる。
- その他の図形: `fill = null`（塗りなし＝従来の見た目）。
- `null` は JSON に残るので**2回目以降は何もしない（冪等）**。保存し直しても壊れない。
- **保存形式の `v` は上げない。** 復元側が `savedEdit.v === 1` の厳密比較なので、上げると
  既存の編集ソース（base・strokes・objects）が丸ごと読めなくなる。

## 11. ツールバー（要望21）

- **文字グリフをアイコン代わりに使うのをやめる。** 従来は14個中8個が文字そのもの
  （`↗` `╱` `▢` `◯` `✕` `T` `▦` `⛶`）だった。既存の `.ie-ic`（24×24 の線画インライン SVG・
  `stroke: currentColor`）と同じ流儀で描き起こす。テキストは「T」ではなく本文の行、
  文字色はパレットの絵にする。
- **名前はボタンの枠の外**に置く。ボタンの中はアイコンだけで、`.ie-toolitem` が
  ボタンとラベル（`.ie-toolname`）を縦に包む。ボタンは 34 → **44px**、アイコンは 19 → **26px**、
  ラベルは 11px・`white-space: nowrap`（「トリミング」でも折り返さない）。
- 同じ形をヘルプ・線色・塗りつぶし・文字色・元に戻す・やり直すにも使う。色ボタンは
  枠の下端に今の色のバーを敷く（線なし・塗りなしは赤い斜線ハッチ）。
- ツールバーは2段。1段目＝描画モード（右端にヘルプ）、2段目＝色・太さ・書式・透過・表示倍率・
  履歴。`.ie-controls { flex: 1 1 100% }` が段を折るので、ヘルプは必ず1段目の右端に来る。
- スライダーは「名前が上・つまみが下」に揃えてボタン群と高さを合わせる。

## 12. 複数選択と既定モード（要望22・23・24）

`selectedId`（単一）を `selectedIds`（選択順の配列）へ作り替える。移動・削除・色・書式・
透過率は**選択中すべて**に効く。

- 不具合: 左クリック押下中の右クリック（ハンド⇄選択の切替）が**テキスト・吹き出しで頻繁に失敗**する。

### 線の太さを選択中の図形へ反映（要望30）

- 従来 `sizeInput` は新規に描くときだけ読まれ、テキストの枠線は `drawTextObj` の `g.lineWidth = o.size`
  ＝**作成時点の値で固定**だった。新規テキストは枠線なしで作り、あとから「線色」で枠線を付ける運用
  （10章）なので、枠線を付けた時点の太さを変える手段が無かった。
- 透過率（12章）と同じ方式にする。`sizeInput` の `pointerdown` で `pushUndo()`（1ドラッグ＝1 undo）、
  `input` で `selectedObjs()` すべての `o.size` を書き換えて `recomposite()`。対象はテキスト・吹き出し・
  矩形・矢印などすべての図形（ペン・ハイライトはラスターなので対象外）。
- `syncSizeUI()`（`recomposite` の末尾）が、選択中があればその太さ（複数なら先頭）、無ければ
  「次に描く太さ」`nextSize` をつまみに映す。`nextSize` は選択が無い状態で動かしたときだけ更新する
  （選択中の図形を細くしただけで、次に描く図形まで細くならない）。

### コマンド切替での設定リセット（要望31）

- 「次に描く」設定は `colorInput.value`（線色）・`lineNone`・`fillValue`・`textColorValue`・`nextSize` の
  5つで、`applyColor` が選択中の図形に色を付けたときも同じ変数を更新するため、直前に触った図形の設定が
  次のコマンドへ持ち越されていた。
- `selectTool(t)` の先頭で `resetDrawStyleIfToolChanged(t)`: 描画ツール（`DRAW_TOOLS`）へ移り、かつ
  直前の描画ツール `lastDrawTool` と違うときだけ、5つを既定（赤 `#ff3b30`・線あり・塗りなし・太さ 6）に
  戻す。選択／ハンド／切り抜きへ移るときと、同じ描画ツールへ戻る（四角 → 選択 → 四角）ときは保持。
  透過率は従来どおりツール別（`toolOpacity`）で対象外。

### 右クリック切替の不具合（原因と対策）

- 原因: 切替を `contextmenu`（右ボタンを**離した**時に発火）で判定していた。ポインタイベントは
  押している最中の別ボタンの押下・解放を `pointerdown`/`pointerup` ではなく **`pointermove`
  （`button` に変化したボタン番号）** で通知し、`pointerup` は**全ボタンが離れたときに最後のボタンで
  1回だけ**来る。Electron 31 で実測した発火順:
  - 左↓ 右↓ 右↑ 左↑ → `pointerdown(0)` `pointermove(2)` `pointermove(2)` `contextmenu` `pointerup(0)`
    … `pendingPlace` が残っているので従来でも効く。
  - 左↓ 右↓ 左↑ 右↑ → `pointerdown(0)` `pointermove(2)` `pointermove(0)` **`pointerup(2)`** `contextmenu`
    … `finish()` が `e.button` を見ずに `pendingPlace` を配置してしまい、テキスト／吹き出しの入力が
    始まる。直後の `contextmenu` は「吹き出し入力中は無視」に当たって切替されない（テキストは入力欄が
    開いたまま既定モードへ戻り、トグルにならない）。
  - 矢印・四角でも同じ順序で起きるが、サイズ 0 の図形は捨てられ、6番目の規則で既定モードへは戻るため
    目立たなかった。
- 対策: 右ボタンを**押した瞬間**（`pointermove` の `button === 2`、描きかけ・配置待ちがある間だけ）に
  `chordToggle()`＝破棄してトグルし、`chord.active` を立てる。立っている間は `pointerdown`／
  `pointermove`／`pointerup` を無視し、`pointerup`（全ボタン解放）と `pointercancel` で下ろす。
  切替から 1 秒以内の `contextmenu` は同じ操作の一部として無視する（二重トグル防止）。
  `finish()` は左以外のボタンで終わった `pointerup` では配置しない（二重防御）。
  `pointerdown` の `button === 2` と `contextmenu` の「描きかけ・配置待ちあり」も `chordToggle()` に
  揃えて保険として残す。6章・12章の表の「3」はこの節の方式に読み替える。

## 17. 線の太さ・透過率の数値入力（2026-09-11）

- 「線の太さ」「透過率」の各スライダーの右に数値入力欄（`.ie-size-num` / `.ie-opacity-num`）を

- 値の適用はスライダー・数値欄とも共通関数（`applySizeValue` / `applyOpacityValue`）に一本化。
  丸め（太さ 1〜40、透過率 0〜90 の整数）→ 両方の欄へ反映 → 選択中の図形があれば即時反映

  （Enter か欄の外クリックで確定）で適用する。
- undo はスライダーが `pointerdown` 時（1ドラッグ＝1操作）、数値欄が `change` 時（1確定＝1操作）。
- フォーカス中の数値欄には値を書き戻さない（入力中のカーソル飛び防止。文字サイズ欄と同じ規約）。
- あわせて、入力欄（INPUT）フォーカス中の Esc は**フォーカスを外すだけ**にした。従来は
  エディタごと閉じて編集内容が破棄されており、数値欄の追加で踏みやすくなるため。
