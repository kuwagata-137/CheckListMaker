# 操作マニュアル（マニュアル/）の仕様（v1.0.13）

利用者向けの使い方の説明が、これまでは `docs/インストールと使い方ガイド.md` の箇条書き
（版ごとの変更点を足していったもの）しかなかった。画面の図と手順で順を追って読める
操作マニュアルを作る（ユーザー依頼 2026-11-11「マニュアルを作ってほしい」
「MultipurposeDiagramMaker の使用説明書がよくできているので、あれみたいなものを作りたい」）。

## 1. 手本

MultipurposeDiagramMaker（以下 MDM）の `マニュアル/`（`MultipurposeDiagramMaker_操作マニュアル_v8.32.docx`）と同じ作りにする。

| MDM の特徴 | CheckListMaker での扱い |
|---|---|
| 原稿 `manual-content.js` → `create-manual.js` が Word を組む（`--preview` で確認用の HTML） | 同じ。`create-manual.js` は MDM のものを写し、名前・版・パスだけ変える |
| 撮影の台本 `capture-puppeteer.js` が、実際の画面を操作して撮り、赤い枠・番号・カーソルの絵・破線の矢印・白い札を重ねる | 同じ。`index.html` を Playwright（または puppeteer）で開いて撮る |
| 1.1「このマニュアルの見方」で記号の凡例を図で示す | 同じ |
| ボタンの実物画像を並べた表（ボタン｜名前｜働き）と、本文中の小さなボタンの絵 | 同じ。メニューバーのボタンを1つずつ撮る |
| 手順表（番号｜説明｜画面）・操作の前後を並べた図・※の補足・ヒントと注意の囲み | 同じ |
| 付録（キーボードショートカット一覧・早見表・困ったときは） | 同じ |
| 表紙（題「操作マニュアル」・アプリ名と版・副題・画面の画像・作成者／作成日／最終更新日／バージョン）・目次・ヘッダー・フッター「Page n / N」 | 同じ |
| 撮った画面は `screenshots/manual/`（Git に入れない）、Word だけをリポジトリで管理 | 同じ |

## 2. 決めたこと

- **形**: Word の操作マニュアル1冊。ファイル名 `マニュアル/CheckListMaker_操作マニュアル_v<版>.docx`。
  アプリの中に使い方の窓は作らない（MDM にもない）。
- **アプリから開く**（2026-11-11 ユーザー指示「アプリのヘルプからマニュアルを開けるようにして」）:
  アプリのメニューに「ヘルプ」を足し、「操作マニュアル」と「バージョン情報」を置く。
  - インストーラは `マニュアル/*.docx` を `resources/マニュアル/` に入れる（`package.json` の `extraResources`）。
    開発中（`npm start`）はリポジトリの `マニュアル/` を読む。
  - 「操作マニュアル」は、アプリの版と同じ名前の .docx（なければ名前の順で最後のもの）を一時フォルダ
    （`%TEMP%\CheckListMaker\`）に写してから、OS の既定のアプリ（Word）で開く。インストール先のファイルを
    Word が掴んだままだと、次の版のインストーラが上書きできなくなるため。処理は `manualfile.js`（テスト対象）と
    `main.js` の `openManual()`。
  - 見つからない・開けないときは、警告の窓で知らせる（.docx を開けるアプリがないときなど）。
  - 「バージョン情報」は、アプリの名前と版を窓で出す（マニュアルの版と見比べるため）。
- **読む人**: CheckListMaker で手順書・チェックリストを作る人と、作った手順書で作業する人。
  開発者向けのこと（ビルド・テスト）は書かない（README と `docs/exe作成ガイド.md` にある）。
- **章立て**:
  1 概要（このマニュアルの見方・2つの型・主な機能）／2 はじめに（インストールと起動・画面構成・メニューバー）／
  3 手順書を作る／4 画像を貼って描き込む（画像編集）／5 画面を撮る（キャプチャ撮影）／
  6 画像をまとめて取り込む（画像インポート）／7 表紙を付ける／8 印刷とファイルの出力／
  9 手順書を見ながら作業する／10 ToDo型のリスト／11 データの保存と受け渡し（インポート・エクスポート・AI）／
  付録 A キーボードショートカット一覧・付録 B 早見表・付録 C 困ったときは
- **文の決まり**: 本文はです・ます（丁寧語だけ。謙譲語を使わない）。表のセルは常体か体言止め。
  ボタンや画面の名前はアプリの表示のまま書く（「フェーズ」「手順」「キャプチャ撮影」「画像インポート」など。言い換えない）。
- **見本**: 架空の手順書「交通費を精算する手順」（架空の「経費精算システム」の操作）だけを使う。
  手順に貼る画像（経費精算システムの画面）も、撮影の台本が HTML で描いて撮る（実在の画面は使わない）。
- **撮影**: `index.html` を開き、デスクトップ版の窓口（`storageAPI`・`recorderAPI` など）をダミーで差し込んで撮る。
  操作はなるべく実際のボタンのクリック・マウスのドラッグで行う（MDM と同じ方針）。
  録画ガジェット（`gadget.html`）と小窓のガイド（`guide.html`）は単独で開いて撮る。
  OS の保存ダイアログや画面全体の撮影など Electron の本物の動きは撮れないので、文で説明する。
- **表紙の作成者**: MDM と同じ「くわがた」。
- **既存のガイド**: `docs/インストールと使い方ガイド.md` はダウンロードとインストールの手順として残し、
  冒頭から操作マニュアルへ案内する。GitHub Actions のビルド成果物（Artifact）には、インストーラと一緒に操作マニュアルも入れる。

## 3. ファイル

| ファイル | 役割 |
|---|---|
| `マニュアル/作成ツール/manual-content.js` | 原稿（ブロックの並び） |
| `マニュアル/作成ツール/capture.js` | 画面の撮影（`npm run manual:shoot`）。`screenshots/manual/` と `_manifest.json` を出す |
| `マニュアル/作成ツール/create-manual.js` | Word を組む（`npm run manual`。`--preview` で `screenshots/manual/_preview.html` も出す） |
| `マニュアル/CheckListMaker_操作マニュアル_v<版>.docx` | 操作マニュアル（リポジトリで管理。インストーラにも入る） |
| `manualfile.js` | 「ヘルプ」→「操作マニュアル」で開くファイルを選び、一時フォルダに写す |

## 4. 作り直し方

画面の見た目・操作・メニューを変えたときと版を上げたときは、原稿と `create-manual.js` の `LAST_UPDATED` を直し、
リポジトリのルートで次を実行する（クラウドのセッションでは `NODE_PATH=/opt/node22/lib/node_modules` を付ける）。

```bash
npm run manual:shoot   # 画面を撮り直す（章を絞るときは node マニュアル/作成ツール/capture.js m03 m04 のように指定）
npm run manual         # Word の操作マニュアルを作る
```

版を上げたら、古い版の .docx は消す（名前に版が入るため）。
