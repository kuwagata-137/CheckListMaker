# 仕様: 項目・手順の文字欄を、文字の量に合わせて縦に伸ばす（v1.0.11）

編集画面の項目の文字欄は1行専用の入力欄で、欄の幅より長い文字は右側が切れて見えなかった。
入力中も横にスクロールするだけで、全文を一度に見られなかった。
本ドキュメントはユーザーとの合意事項を確定仕様として記録する（運用ルール 領域1）。

- 決定日: 2026-10-05（ユーザー要望「テキスト量に応じてテキスト欄が自動で大きくなるように。編集中も同様」、
  質問への回答「Enter で改行できる」）
- 実装: `index.html`（`renderItem` / `renderStep` / `textareaBody` / `fitGrowFields`、CSS）、
  `xlsx-export.js`（行の高さ）、`guide.html`（小窓）、AI スキルの `data-format.md` / `json-to-html.mjs`。
  テストは `test/itemtextwrap.test.js`。

## 対象の欄（編集画面）

| 欄 | 型 |
| --- | --- |
| 項目の文字 `text` | ToDo 型 |
| 手順の文字 `text` | テンプレート型 |
| メモ `note` | テンプレート型 |

セクション名・フェーズ名・チェックリストの題名は対象外（見出しで短く、題名はファイル名にも使うため改行を入れない）。

## 欄の動き

- 文字が欄の右端に届いたら折り返し、欄の高さが文の行数に合わせて伸び縮みする。表示中も入力中も同じ。
- **Enter キーで改行が入る**（textarea の標準どおり）。日本語入力の変換確定は今までどおり。
- 欄が複数行になったとき、つかみ手⠿・チェック欄・↑↓⤒✕ボタン・所要時間の欄は **1行目の高さにそろえる（上ぞろえ）**。
- 高さの自動調整は CSS の `field-sizing: content`（Electron 31＝Chromium 126 で有効）。これが効かないブラウザ
  （HTML 保存したファイルを Firefox などで開いた場合）だけ、JS で `scrollHeight` に合わせる。

### 既存の不具合もあわせて直る

データにはもともと改行が入り得た（手順を統合したメモは `\n` で連結される、録画の取り込み画面の手順文の欄は
textarea で改行を打てる）。以前の1行の入力欄は改行を取り除いて表示し、欄を触って離れると改行の消えた値で
保存していた。textarea にしたことで、改行はそのまま表示・保存される。

## 出力での改行の扱い

手順や項目を1件ずつ全文で見せる出力は、改行した位置で行を変える。一覧で全体を見渡すための出力は、
今までどおり1行にまとめる（改行は空白になる）。

| 出力 | 改行 |
| --- | --- |
| 印刷・PDF の本文（手順の文字・メモ・ToDo の項目） | 行を変える（`white-space: pre-line`） |
| Word | 行を変える（`\n` → `<br>` → Word の改行 `w:br`） |
| Excel | 行を変える（セル内改行。行の高さは text・note・詳細の最大行数から決める） |
| 作業開始の全画面（手順の文字・メモ） | 行を変える |
| 小窓（広げた状態） | 行を変える |
| AI スキルのプレビュー（`json-to-html.mjs`） | 行を変える |
| 印刷の目次 | 1行のまま |
| サムネイルサイドバー | 1行のまま |
| 作業結果の集計表 | 1行のまま |
| 小窓（たたんだ状態） | 1行のまま |
| 取り込み時の挿入位置の帯 | 1行のまま |
| CSV・HTML 保存・共有リンク・JSON | もともと改行を保つので変更なし |
