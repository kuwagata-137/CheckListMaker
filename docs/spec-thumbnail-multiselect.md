# 仕様: サムネイルの複数選択（まとめて削除・移動）（v1.0.8・作業1）

## 要望と決定

- 要望（2026-09-29）：「サムネイルで Ctrl+選択や Shift+選択等で複数選択して削除や移動ができるようにしたい」
- 決定（AskUserQuestion の回答）：
  - まとめて削除の安全策は「確認と Ctrl+Z の両方」。Ctrl+Z／Ctrl+Y をアプリの元に戻す・やり直しにつなぐ。
  - 見た目はモック（`screenshots/mock-thumbs-multiselect.png`）のとおり。
  - **削除の確認はサイドバーからの削除なら1件でも出す**（Delete キー・選択バーの［削除］・カードの ✕）。
    本文側の手順の削除ボタンは今のまま（確認なし）。※モック確認時に「2件以上だけ」→「やはり1件でも確認する」に変更。

## 操作

| 操作 | 動き |
|---|---|
| クリック | 今までどおり本文へジャンプ。選択はその1枚（Shift の範囲の起点） |
| Ctrl+クリック | 1枚ずつ足す／外す。本文へはジャンプしない（サイドバーにフォーカスを置く） |
| Shift+クリック | 起点からの範囲（フェーズをまたいでよい）。Ctrl+Shift+クリックは範囲を足す |
| Ctrl+A／Esc／空白クリック | 全部選ぶ／選択を外す／選択を外す（Ctrl+A・Esc はサイドバーにフォーカスがあるとき） |
| 選択中のカードの ⠿ をドラッグ | 選んだ手順をまとめて移動。ドロップ位置に番号順で固まる。移動後も選択を残す |
| 選択していないカードの ⠿ をドラッグ | 今までどおりその1件だけ |
| Delete／Backspace（サイドバーにフォーカス） | 選択中を削除。**1件でも確認**：2件以上は「選択した N 件の手順を削除しますか？」、1件は「手順 3「…」を削除しますか？」。1回の削除＝元に戻す1回。削除後に右下へ「N件の手順を削除しました（Ctrl+Z で元に戻せます）」 |
| カードの ✕ | その1件だけ。**確認を出す**（v1.0.7 までは確認なし）。削除後の通知も同じ |
| 選択バー（2件以上のとき見出しの下） | 「N件選択中」［削除］［選択解除］ |
| 本文の手順にフォーカスが入る | 選択はその1件に戻る |

- ToDo 型は「手順」を「項目」と読み替える。
- 非対象：囲み選択、矢印キーでの選択、本文側の複数選択、↑↓ボタンの複数対応、右クリックメニュー。

## 見た目（モック承認済み）

- 選択中：青い枠と薄い地色（1件だけのときは今の「編集中」の見た目と同じ）。
- 2件以上：地色を少し濃くし、番号を青丸で塗る（`#thumbs.has-multi`）。見出しの下に選択バー。
- 編集中（本文でフォーカスのある手順）で選択していないカードは、番号だけ青。
- まとめてドラッグ中：選んだカードが半透明。ドラッグの絵は最初の1枚の縮小画像に「N件」の札。
- `.tsb-card` は文字選択しない（Shift+クリックで文字が選択されないように）。

## Ctrl+Z／Ctrl+Shift+Z／Ctrl+Y

- document の keydown で `store.undo()`／`store.redo()`。
- 何もしないとき（それぞれの標準の動きに任せる）：入力欄・テキストエリア・セレクト・リッチ本文
  （contenteditable）にフォーカスがあるとき、画像編集（`html.ie-open`）、モーダル（印刷プレビューなど）、
  実行モードの表示中。

## 既存の不具合（コードを読んで判明・テストで再現してから直す）

1. **同じフェーズ内で下へドラッグすると、破線より1つ下に入る**（本文側も同じ）。ドロップ位置は動かす前の並びで
   数えるのに、`M.moveItem` は先に取り除いてから差し込むため。→ 新しい `M.moveItems(checklist, ids, toSection, toIndex)`
   は toIndex を「表示上の位置」として受け取り、挿入位置より前にある動かす手順の数だけ詰めて換算する。
   本文・サイドバーのドラッグとも `M.moveItems` を使う（↑↓ボタンは `M.moveItem` のまま）。
2. **ドロップ直後の再描画でドラッグの状態が残る**。ドラッグ元の要素が描き直しで消えるため `dragend` が届かず、
   あとで別のもの（外部の画像ファイルなど）をドロップしたときに、前の手順が動くおそれがあった。→ `drop` の最後で片づける。
- 位置が変わらないドロップはコミットしない（元に戻す履歴を汚さない）。

## 実装

- 純関数（`window.__test__`）：`nextThumbSelection(order, sel, anchor, target, { ctrl, shift })` →
  `{ sel, anchor }`、`M.removeItems(checklist, ids)`、`M.moveItems(checklist, ids, toSection, toIndex)`。
- 選択は変数 `thumbSel`（Set）と `thumbAnchor`。表示は class の付け替え（`markThumbSelection`）だけで行い、
  サイドバーを描き直したときも付け直す（消えた手順は外す）。
- `attachDragAndDrop` に任意の `opts.dragIds(itemId)`（動かす手順の一覧）を足し、`onMove` に `itemIds` を渡す。
- `#thumbs` に `tabindex="-1"` とキー操作・空白クリックを1回だけ配線（`ensureThumbsEl`）。
